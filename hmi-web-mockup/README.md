# 불량 선별 HMI (웹)

불량품 감지 시스템의 조작 화면입니다. 최종 형태는 웹으로 확정했고, 화면은 React(`react/`)로 만듭니다.
대시보드(감시 화면) 두 개는 없애고 조작 화면 하나만 React로 옮겼습니다 (사용자 2026-10-17). 옛 화면은 git 기록과 [docs/v1-snapshot/](../docs/v1-snapshot/)에 있습니다.
실제 서버와는 **웹소켓 하나로 XML을 주고받습니다** — 서버 담당의 규약 v1.0([docs/server-xml-v1.0.md](../docs/server-xml-v1.0.md)), HMI 쪽 사용법과 요청안([docs/xml-protocol.md](../docs/xml-protocol.md)).
서버 PC가 없을 때는 브라우저 안의 가짜 서버(`js/mock-server.js`, 기본값 `useMock: true`)가 [API 초안 v0.5](../docs/API.md)(HTTP·JSON)대로 응답합니다.
서버가 컨베이어·로봇팔과 주고받는 약속은 [컨베이어 시리얼 규약](../docs/conveyor-protocol.md) · [로봇팔 제어 약속](../docs/arm-control.md) · [공정 순서](../docs/line-sequence.md)에 있습니다.
실제 서버에 붙일 때는 [서버 점검](tools/server-check.html)(형식 XML)으로 먼저 확인한 뒤 `js/config.js`를 맞춥니다.
로봇팔 키트(SO-ARM101 기반)에 맞춘 값과 설치 순서는 [로봇팔 문서](../docs/robot-arm.md)에 있습니다.

## 실행

조작 화면은 React(Vite)로 만듭니다 (`react/`, Node.js 필요). 처음 한 번 패키지를 받습니다.

```bash
npm --prefix hmi-web-mockup/react install
```

화면을 고치면서 볼 때는 Vite 개발 서버를 띄웁니다 (미리보기 설정 `hmi-react`). 고치면 바로 반영되고, 기본은 브라우저 안 가짜 서버입니다.

```bash
npm --prefix hmi-web-mockup/react run dev
```

| 주소 | 화면 |
|---|---|
| `http://localhost:5174/` | 조작 화면 — 가짜 서버 (개발용 장치 연결 표시 포함) |
| `http://localhost:5174/?mock=0&ws=ws://서버IP:5080/ws/hmi` | 조작 화면 — 실제 서버 |

빌드하면 `react/dist/`에 서버에 올릴 파일이 생깁니다. 빌드한 화면은 가짜 서버를 쓰지 않고, 자기를 내준 서버의 `/ws/hmi`에 붙는 것이 기본입니다 (`react/src/server-defaults.js`).
조작 화면은 모듈 스크립트라 파일을 더블클릭해서는 열리지 않습니다 — 서버로 엽니다.

```bash
npm --prefix hmi-web-mockup/react run build
```

빌드한 화면과 점검 페이지는 개발용 정적 서버로 엽니다. 메인 서버 묶음과 같은 배치(`/`는 빌드한 조작 화면, `/tools/…`는 점검 페이지)로 내주고, 파일을 캐시하지 않습니다.

```bash
python hmi-web-mockup/tools/dev-server.py 5173
```

| 주소 | 화면 |
|---|---|
| `http://localhost:5173/?mock=0&ws=ws://서버IP:5080/ws/hmi` | 빌드한 조작 화면 (가짜 서버로 보려면 `?mock=1`). 고친 뒤에는 다시 빌드 |
| `http://localhost:5173/tools/devices.html` | 장치 점검 — 로봇팔 서보·자세 저장·USB 카메라·컨베이어(아두이노) 규약 점검 (설치·고장 확인용) |
| `http://localhost:5173/tools/server-check.html` | 서버 점검 — 서버 형식 확인과 `config.js` 제안 값 |

다른 PC에서도 열려면 이 PC의 장비망 주소로 받게 띄웁니다 (미리보기 설정의 `hmi-web-mockup-lan`과 같음).
서버가 이 PC의 IPv4 주소를 알려 주고, 다른 PC는 `http://<이 PC 주소>:8080/?mock=0&ws=ws://<서버 주소>:5080/ws/hmi`로 엽니다 (빌드한 조작 화면).
같은 망에 있어야 하고(브라우저가 서버에 직접 붙음), Windows 방화벽이 Python의 접속을 막으면 허용해야 합니다. 인증이 없으니 믿을 수 있는 망에서만 씁니다.
(2026-10-17 React로 옮기기 전 화면이 다른 PC에서 실제 서버에 붙는 것을 확인 — 사용자. React 화면은 이 PC에서 같은 주소 형식(`localhost:8080`)으로 실제 서버에 붙는 것까지 확인.
Claude 앱 안의 브라우저는 이 PC의 장비망 주소에서 서버로 나가는 접속을 막아 확인에 쓸 수 없음)

```bash
python hmi-web-mockup/tools/dev-server.py 8080 --host 0.0.0.0
```

### 메인 서버에 올리기

HMI 화면을 서버 담당의 메인 서버가 직접 내주게 하면, 화면과 통신이 한 서버(`http://서버:5080/`)로 모입니다.
아래 명령이 React 조작 화면을 빌드해 메인 서버용 묶음을 만듭니다 (npm 필요, 이미 빌드했으면 `--no-build`). zip 안의 `wwwroot/`를 서버 프로젝트(`src/Ecp.HmiServer/`)에 넣고 서버에서 정적 파일을 켜면 됩니다.
서버 쪽 할 일은 zip 안의 `README-server.md`와 [서버 답장 0.1](../docs/hmi-server-answer-1.md)에 있습니다.

```bash
python hmi-web-mockup/tools/make-server-bundle.py hmi-main-server.zip
```

- `wwwroot/`에는 React 조작 화면(`index.html`·`assets/`), 점검 페이지(`tools/`)와 점검 페이지가 읽는 `js/`·`css/`·`config/`가 들어갑니다. 시험·개발 도구와 React 소스는 빠집니다.
- 조작 화면은 주소 뒤에 아무것도 붙이지 않아도 화면을 내준 서버의 `/ws/hmi`에 붙습니다 (https면 `wss`). 점검 페이지용 `js/config.js`도 메인 서버용으로 바뀝니다(`useMock: false`, `wsUrl: 'auto'`).
- 이 구성을 시험용 서버로 흉내 내려면 빌드한 뒤 `python hmi-web-mockup/tests/xml-server.py 5091 --simulation --static hmi-web-mockup/react/dist`를 띄우고 `http://localhost:5091/`을 엽니다 (미리보기 설정 `xml-server-hosting`).

주소 뒤에 붙이는 설정 (설정 파일보다 우선)

| 붙이는 것 | 뜻 |
|---|---|
| `?dev=0` / `?dev=1` | 배포 화면 / 개발 화면 (장치 연결·흉내 버튼) |
| `?theme=light` · `dark` · `auto` | 테마 고정 |
| `?mock=0` · `?mock=1` | 실제 서버 · 가짜 서버 (개발 서버는 가짜, 빌드한 화면은 실제 서버가 기본) |
| `?ws=…` | 서버 주소 (예: `?mock=0&ws=ws://192.168.0.10:5080/ws/hmi`). `?ws=auto`면 화면을 내준 서버의 `/ws/hmi` |
| `?homePose=0` | 원점 복귀 때 원점 각도를 붙이지 않음 (각도를 아직 받지 않는 서버 v1.0용) |
| `?format=json&api=…&push=…` | 예전 JSON 서버 (`push`: `socketio` · `sse` · `poll`) |

XML 서버 없이 XML 연결을 시험하려면 시험용 XML 서버(서버 v1.0 흉내, 실제 서버 아님)를 띄웁니다. 서버 담당 회신(2026-10-16)으로 더해진 것(원점 각도 검사·긴급정지 해제 받기)까지 흉내 냅니다.
`--simulation`은 값이 움직이고, `--extended`는 [요청안](../docs/xml-protocol.md#4-서버에-요청할-것-v10-다음-제안)도 흉내 냅니다.

```bash
python hmi-web-mockup/tests/xml-server.py 5080 --simulation
```

그다음 `http://localhost:5174/?mock=0&ws=ws://localhost:5080/ws/hmi`.

가짜 서버는 조작 화면을 여러 창에 띄워도 **하나를 나눠 씁니다** (`js/mock-hub.js`). 화면에 보이는 탭이 서버를 맡고,
그 탭을 닫거나 다른 탭이 보이면 마지막 상태에서 이어 갑니다.

가짜 서버는 [공정 순서](../docs/line-sequence.md)의 "부품마다 멈춤"대로 돕니다. 가짜 컨베이어(`js/conveyor.js`의 가짜 아두이노, 규약 그대로)가 부품을 검사 자리로 옮겨 멈추면 판정하고,
양품은 내보내며 불량품은 로봇팔 작업(정해 둔 자세 + 학습 정책 흉내)으로 불량 상자에 옮깁니다. 지난 기록(`GET /history`)도 답해서, 화면을 새로 열거나 다시 연결되면 로그가 채워집니다.

개발 화면 아래쪽 장치 버튼을 누르면 그 장치의 연결 끊김을 흉내 냅니다. 컨베이어 버튼은 USB를 뽑은 것처럼 응답을 끊어, 서버 쪽 견본이 응답 없음 3번으로 알아채게 합니다.
서보 과열·전압 이상(리더에 12V)·판정 지연·집기 실패·부품 걸림·컨베이어 정지 단추 흉내는 가짜 서버(`js/mock-server.js`)에 남아 있지만, 누르는 단추는 대시보드와 함께 없앴습니다 (시험 `tests/mock-server.test.js`에서 씀).
가짜 서버에는 카메라 영상이 없습니다 — 카메라를 연결하면 그렇다고 안내합니다 (가짜 영상은 실제 카메라를 쓰면서 뺐습니다, 사용자 2026-10-17).

## 화면

### 조작 화면 (`react/src/App.jsx`)

| ID | 기능 | 위치 |
|---|---|---|
| F-01 | 프로젝트 시작 | 조작반의 주 버튼(라이트는 검정, 다크는 흰색). 가동 중에는 같은 키가 "정지"가 됨 |
| F-02 | EMS / 긴급정지 | 노란 판 위 빨간 버튼. 해제는 "긴급정지 해제" → 확인 창 |
| F-03 | 프로그램 종료 | 조작반 맨 아래. 확인 창 → HMI만 닫고 종료 화면. 서버에는 보내지 않아 라인과 장비는 그대로 (장비 정지는 정지 키·긴급정지) |
| F-04 | 원점 복귀 · 원점 잡기 | 시작 키 아래 두 키. 원점은 **이 HMI(브라우저)가 저장**합니다 (`js/home.js`, [xml-protocol 3장](../docs/xml-protocol.md#3-원점--hmi가-저장-사용자-2026-10-14)). **원점 잡기**: 수동 모드에서(가동 중에도) 리더암으로 로봇팔을 원하는 자세에 둔 뒤 누르면 확인 창을 거쳐 그 자세를 원점으로 저장. **원점 복귀**: 자동 모드·정지 상태에서 저장된 원점 각도를 서버에 보내 이동. 다른 모드에서는 키가 잠기고, 마우스를 올리면 이유가 보임 |
| F-05 | 카메라 연결 | 오른쪽 큰 화면 가운데 버튼. 연결되면 주 카메라 영상 + 판정 상자, 오른쪽 위 "카메라 끄기" (이 PC의 USB 카메라는 끄기 없음) |
| F-06 | 운전 모드 전환 | 자동 / 수동. 정지 상태에서만. 수동이면 리더암 각도 표시 |

추가 기능
- **생산 통계**: 카메라 아래 검사·양품·불량·불량률
- **로그**: 오른쪽 맨 아래 "로그" 버튼 → 로그 창에서만 봅니다. 창은 오른쪽 보기 영역 위에만 떠서
  열려 있어도 왼쪽 조작반(긴급정지 포함)을 그대로 누를 수 있습니다. 닫기 버튼, Esc, 로그 버튼으로 닫습니다.
- **로그 알림 점**: 창이 닫혀 있는 동안 확인이 필요한 기록(경고·비상)이 생기면 로그 아이콘 오른쪽 위에 빨간 점이 켜지고,
  창을 열면 꺼집니다. 불량 검출은 정상 공정에서 늘 생기므로 점을 켜지 않습니다 (통계에서 확인).
  켜는 기준은 `react/src/App.jsx`의 `NOTIFY_LEVELS`, `NOTIFY_SKIP`에서 바꿉니다.
- **고장 표시**: 서버가 고장(`fault`, 예: 서보 과열)으로 멈추면 상태 표시등이 노랑이 되고 이유를 씁니다. 그동안 시작을 누르면 이유를 다시 알려 줍니다.
  고장마다 풀리는 방법(원인이 사라지면 · 원점 복귀 · 확인하고 시작)을 함께 씁니다 ([API 3.1](../docs/API.md) `clear`).
- **원점 필요**: 긴급정지나 로봇팔 고장 뒤에는 원점 복귀를 해야 자동으로 시작할 수 있습니다(`home_required`). 이 HMI에 저장된 원점이 없으면 수동 모드에서 원점 잡기를 하라고 알리고 자동 시작을 보내지 않습니다. 둘 다 상태 설명과 시작·원점 키 아래에 씁니다. 수동 모드의 시작은 막지 않습니다(사람이 리더암으로 팔을 움직임).
- **상태 미수신**: 서버가 라인 상태를 보내지 않으면(XML 서버 v1.0) 상태 표시가 "상태 미수신"이고 키를 막지 않습니다. 명령마다 서버의 답을 키 아래에 씁니다 — 받기만 했으면 "아직 장비는 움직이지 않습니다", 긴급정지는 "장비를 멈추지 않았습니다 → DC 전원 케이블".
- **원점 잡기 안내**: 수동 모드에서는 원점 키 아래에 쓰는 법과 마지막으로 저장한 때를 씁니다 (누른 뒤 저장됐는지 여기서 보임).
- **지난 기록**: 서버가 기록 조회(`GET /history`)를 주면 화면을 열 때 지난 로그를 채우고(이때는 알림 점을 켜지 않음), 다시 연결되면 끊긴 동안의 기록을 시각 차례로 끼웁니다.
- **서버 끊김 안내**: 화면 긴급정지가 듣지 않으므로 "로봇팔과 컨베이어의 DC 전원 케이블을 뽑으세요" (키트 설명서의 비상 정지 방법)
- **다크 모드 버튼**: 오른쪽 맨 아래, 로그 버튼 왼쪽
- **장치 연결 상태** (개발용): 맨 아래 줄 왼쪽. 서버가 알려 준 장치(카메라 여러 대 포함)를 그대로 보입니다

## 테마 (라이트 / 다크)

처음 열면 PC의 라이트/다크 설정을 따릅니다(`auto`). 오른쪽 맨 아래 **"다크 모드"** 버튼으로 바꿀 수 있고,
켜져 있으면 눌린 모양으로 보입니다. 고른 값은 그 브라우저에 저장되어 새로고침해도 유지되고, 점검 페이지도 같은 값을 씁니다.

적용 순서: 주소의 `?theme=` → 버튼으로 고른 값 → `js/config.js`의 `theme`. 조작 화면은 그리기 전에 `react/index.html`이 같은 순서로 정합니다.

두 테마는 색 토큰만 다르고 배치·크기·글자는 같습니다. 색 토큰은 `css/base.css` 위쪽의
`prefers-color-scheme: dark` 블록과 `:root[data-theme="dark"]` 블록 두 곳에 같은 값으로 들어 있으니, 고칠 때는 둘 다 고칩니다.

## 시험

```bash
node --test "hmi-web-mockup/tests/*.test.js"
```

React 화면 자체(`react/src/`)는 자동 시험이 없고 브라우저로 확인합니다. 시험하는 통신·상태 파일(`js/`)은 React 화면이 그대로 불러 씁니다.

| 시험 | 내용 |

## 디자인 원칙

1. **색은 신호다.** IEC 60073 표시등 의미로만 쓴다. 빨강 = 비상, 노랑 = 이상·진행 중, 초록 = 정상 가동. 나머지는 회색 (ISA-101).
   예외 하나: 로그 버튼의 알림 점은 흔히 쓰는 알림 표시 관례대로 빨강이다.
2. **대담함은 한 곳에만.** 화면에서 튀는 것은 긴급정지 하나. 실제 비상정지 스위치처럼 노란 판 위 빨간 버섯머리.
3. **가장 중요한 것은 왼쪽 위.** 상태 → 긴급정지 → 시작 순서로 읽힌다.
4. **못 누르는 버튼은 이유를 쓴다.** 실패하면 그 버튼 아래에 무엇이 문제이고 어떻게 하면 되는지 쓴다.
5. **장식 없음.** 그림자·그라디언트·블러 0. 깊이는 회색 단계와 1px 테두리로만. 틀은 실제 화면(카메라)에만.
6. **테마가 바뀌어도 안전 색은 그대로.** 긴급정지(노란 판 위 빨간 버튼)는 ISO 13850 고정색이라 두 테마가 같다.
   다크는 위에 올라온 면일수록 밝게(조작반 판 → 보기 영역 → 키·창) 한다.
