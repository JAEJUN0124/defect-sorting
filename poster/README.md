# 프로젝트 포스터

불량품 선별 프로젝트 포스터입니다. A1(594 × 841 mm)을 기준으로 그렸습니다. A 규격은 가로세로 비율이 같아서 A0~A3 어느 크기로 뽑아도 그대로 맞습니다. 7·8안은 제출 규격인 595 × 835 mm로 그렸습니다.

**최종안은 8안입니다** (2026-10-27 채택). 제출·인쇄에는 `v8/poster.pdf`를 씁니다. 이 폴더 바로 아래의 `poster.pdf`·`poster.png`·`poster.svg`는 6안입니다.

| 파일 | 내용 |
|---|---|
| `poster.pdf` | 6안 인쇄용. 글꼴이 파일 안에 들어 있어 다른 PC에서도 똑같이 보입니다 |
| `poster.png` | 6안 미리보기 (1188 × 1682) |
| `poster.svg` | 6안 원본 벡터. 일러스트레이터에서 열 수 있지만, 그 PC에 글꼴 Noto Sans KR이 있어야 합니다 |
| `build.py` | 위 세 파일을 만드는 스크립트 |
| `assets/daelim-authority-mark.svg` | 대림대학교 Authority Mark. 학교가 배포한 .ai 파일에서 벡터를 그대로 뽑았습니다 |
| `v1/` | 1안. 그림과 제목만 있고 동작 설명은 없습니다 |
| `v2/` | 2안. 동작 과정·시스템 구성을 소제목과 여러 줄 설명으로 넣었습니다 |
| `v3/` | 3안. 문구를 줄이고 남색·산호·남색 세 띠로 정보를 나눴습니다 |
| `v4/` | 4안. 1안의 색 배치로 돌아가, 카메라·불량품·로봇팔을 한 장면에 넣고 설명은 두 줄로 줄였습니다. 하늘과 바닥의 경계는 1안처럼 가운데보다 조금 아래입니다 |
| `v5/` | 5안. 4안과 그림·글은 같고, 세로 3분할의 1 : 2로 위 1/3은 하늘, 아래 2/3는 바닥입니다 |
| `v6/` | 6안. 인자 없이 돌린 `build.py`가 이 폴더 바로 아래에 만드는 안(`LATEST`)입니다. 1안의 구도·제목 크기·색 면적을 그대로 두고, 최신 안의 카메라와 불량품 모양만 옮겼습니다. 1안의 두 줄 설명을 한 줄로 줄이고 그 자리에 작동 과정·시스템 구성을 넣었습니다 |
| `v7/` | 7안. 제출 규격 595 × 835 mm. 1안의 그림을 0.9배로 줄여 42 mm 올리고, 넓어진 바닥에 작동 과정 세 단계와 시스템 구성도를 넣었습니다. Make Poster 플러그인 형식의 HTML(`poster.html`)이 원본입니다 |
| `v8/` | 8안, **최종안**. 7안과 그림·크기·설명이 같고, 제목을 "불량을 찾는 눈, / 골라내는 손"으로 바꿔 눈(카메라)이 찾고 손(로봇팔)이 고른다는 것이 제목에서 읽히게 했습니다. 2026-10-27에 머리를 두 줄로 바꿨습니다: 로고 옆 "대림대학교 / 스마트소프트웨어학과", 오른쪽 "2026 캡스톤 디자인 / 팀원" (아래 "8안") |
| `v9/` | 9안. 8안에 설명을 더한 안입니다 (교수 의견 "설명이 부족", 2026-10-27). 그림과 제목을 줄이고 소개 두 줄, 작동 과정 네 단계, 운전 모드·긴급정지, 웹 HMI 주요 기능, 영상 연결을 더했습니다 (아래 "9안") |

`v1/`~`v3/`에는 결과물(PDF·PNG·SVG)만 있고 다시 만들지 못합니다. 고쳐야 하면 각 폴더의 `poster.svg`를 직접 엽니다. 4·5안은 `build.py`의 `LAYOUTS`에 안마다 값이 있고, 6안은 `v1/poster.svg`를 읽어 고치므로 셋 다 다시 만들 수 있습니다.

## 6안

1안을 만든 스크립트가 남아 있지 않아, `build.py`는 `v1/poster.svg`를 읽어 아래 세 곳만 바꿉니다(`restored_v1()`). 글자는 `TEXT`에서 넣습니다. 그래서 `v1/poster.svg`의 그림을 고치면 6안도 따라 바뀝니다.

| 바꾼 곳 | 1안 | 6안 |
|---|---|---|
| 카메라 | 없음 | 4안 이후의 카메라를 그대로. 검사 자리 바로 위에서 내려다보고, 점선 두 줄이 불량품을 집은 그리퍼 양옆으로 내려옵니다 |
| 불량품 | 남색, 모서리 깨짐 | 같은 자리·크기(12 mm)에 산호색 금을 더했습니다 |
| 설명 (기준선 735·762) | 두 줄 설명 | 첫 줄은 한 줄로 줄인 설명(`TEXT['description']`). 둘째 줄은 작동 과정·시스템 구성으로, 아래 학과·팀원 줄처럼 앞 칸은 왼쪽, 뒤 칸은 오른쪽 여백에 맞춥니다. 설명보다 한 단계 작게(16) 씁니다 |

그 밖의 구도, 제목(54 mm, 굵기 600), 하늘과 바닥의 경계(493 mm, 약 59 : 41), 원, 로봇팔 자세, 별, 바닥에 비친 원, 학교·사업명, 학과·팀원은 1안과 같습니다. 1안의 미리보기와 픽셀로 비교해 카메라·불량품·설명 두 줄 밖은 바뀌지 않은 것을 확인했습니다.

## 7안

1안을 바탕으로 작동 과정과 시스템 구성을 더한 안입니다. 자세한 설명은 넣지 않고 단계마다 한 줄씩만 씁니다. `build.py`의 `v7_html()`이 `v1/poster.svg`에서 별·원·비친 원·로봇팔·학교 마크를 가져와 HTML 한 장으로 짭니다.

종이는 제출 규격인 595 × 835 mm(`V7_W`, `V7_H`)로, A1보다 가로 1 mm 넓고 세로 6 mm 짧습니다. 그림을 늘리거나 줄여 맞추지 않았습니다. 가로는 가운데 축을 297.5로 옮기고 오른쪽 맞춤 글자와 컨베이어 끝을 1 mm 늘렸고, 세로는 그림·제목·설명·학과 줄 사이를 조금씩 당겼습니다. 글자 크기와 위·옆·아래 여백은 1안과 같습니다. 미리보기 PNG는 1188 × 1667입니다.

| 바꾼 곳 | 1안 | 7안 |
|---|---|---|
| 그림 | 원·로봇팔이 검사 자리(480)에 닿음 | 검사 자리를 중심으로 0.9배로 줄여 438로 올림. 원 꼭대기는 1안과 거의 같은 높이이고, 컨베이어 띠는 1안처럼 양옆 여백(40)까지 닿습니다 |
| 카메라·불량품 | 카메라 없음 | 6안과 같은 카메라와 금 간 불량품 |
| 바닥에 비친 원 | 약 80 mm | 0.45배 깊이 |
| 설명 | 두 줄 | 6안의 한 줄 설명 아래에 작동 과정(이송 → 판정 → 분류)과 시스템 구성(웹 HMI ↔ 서버 ↔ 컨베이어·카메라 2대·로봇팔·리더암) |

제목 크기·굵기, 학교·사업명, 학과·팀원 줄은 1안과 같습니다. 글자는 모두 `TEXT`(`steps`, `system` 포함)에서 넣습니다.

## 8안

7안과 같은 틀(`v7_html()`)로 만듭니다. 틀로 만드는 안과 안마다 다른 값은 `V7_VERSIONS`에 있습니다. 7안은 그대로 두었습니다.

| 바꾼 곳 | 7안 | 8안 |
|---|---|---|
| 제목 | "불량을 골라내는 / 눈과 손" | "불량을 찾는 눈, / 골라내는 손" (`TEXT['title_v8']`) |
| 머리 왼쪽 | 로고 옆에 "대림대학교" 한 줄 | 두 줄: "대림대학교"(20, 굵게) / "스마트소프트웨어학과"(13.5). 두 줄 덩어리(46~87 mm, 41 mm)가 로고(38~96 mm, 58 mm)의 가운데 67에 옵니다 (2026-10-27) |
| 머리 오른쪽 | "2026 경기도 앵커 사업" | 두 줄: "2026 캡스톤 디자인"(`TEXT['program_v8']`) / 팀원 세 명. 왼쪽 두 줄과 같은 기준선(63 · 86, `V8_HEAD`)이라, 예전 맨 아래 줄(학과 왼쪽, 팀원 오른쪽)이 머리 둘째 줄로 올라간 모양입니다 |
| 맨 아래 줄 | 학과·팀원 | 없음. 시스템 구성 상자의 아래 끝을 그 줄의 기준선(799)에 맞춰 아래 여백을 7안과 같은 36 mm로 두고, 늘어난 31 mm를 작동 과정 위·아래 두 틈에 반씩 나눴습니다 (25 · 23 → 40.5 · 38.5) |
| 별 | 40개 | 39개. 팀원 이름 바로 아래(5 mm)의 별 하나가 점처럼 읽혀, 머리 글자 둘레 8 mm 안의 별을 뺍니다 (`V8_STAR_CLEAR`) |

글자는 모두 위아래 30 mm, 좌우 38 mm 안전 여백 안에 있고, PDF는 595 × 835 mm 한 쪽, 래스터 그림 없음(글자는 Type3 모양)으로 바꾸기 전과 같습니다.

## 9안

8안을 바탕으로 설명을 더한 안입니다 (교수 의견 "설명이 부족", 2026-10-27). 머리·색·그림·제목 문구·글자 모양은 8안과 같고, 그림과 제목을 줄여 생긴 자리에 칸을 더했습니다. 본문은 `v9_content()`, 자리는 `V9_*`, 글은 `TEXT`의 `*_v9`입니다.

| 바꾼 곳 | 8안 | 9안 |
|---|---|---|
| 그림 | 0.9배, 검사 자리 438 | 0.68배, 검사 자리 353 (`V9_ART`). 원 꼭대기는 116으로 머리 아래 20. 컨베이어 부품은 양끝 롤러 안쪽까지 오도록 8개씩 |
| 제목 | 54 mm, 기준선 538 · 602 | 44 mm, 433 · 485 (글자 사이는 같은 비율) |
| 소개 | 한 줄 (17) | 두 줄 (14): 무엇을 하는 라인인지 + 작업자가 웹 HMI로 하는 일 |
| 작동 과정 | 세 단계, 한 줄 설명 | 네 단계(이송 · 촬영 · 판정 · 분류), 두 줄 설명 |
| 운전 모드 · 긴급정지 | 없음 | 두 칸. 자동 / 수동(리더암), 누르면 / 해제 (D-003 · D-004 · D-007) |
| 웹 HMI 주요 기능 | 없음 | 상자 하나에 여덟 칸 (시작·정지, 원점, 옮길 부품, 카메라, 생산 통계, 장치 연결, 로그·알림, 밖에서 접속) |
| 시스템 구성 | 웹소켓 · XML | 화살표 위 웹소켓 · XML, 아래 영상 · MJPEG. 자리는 8안 그대로 (상자 아래 끝 799, 아래 여백 36) |

칸 사이는 약 12 mm로 고르게 두었습니다. 글은 공정 순서·HMI 문서와 결정에 있는 것만 쓰고, 팀이 정하지 않은 장치 규칙(긴급정지 때 로봇팔 힘 빼기 등)과 판정 방법은 적지 않았습니다. 글자는 모두 안전 여백 안이고 서로 겹치지 않으며, PDF는 595 × 835 mm 한 쪽, 래스터 그림 없음입니다.

```bash
python poster/build.py v9
```

PDF에는 래스터 그림이 없고 글자도 모양(Type3)으로 들어가 있어, 크게 뽑아도 깨지지 않고 인쇄소 PC에 글꼴이 없어도 똑같이 나옵니다. 색은 RGB입니다.

`poster.html`은 Make Poster 플러그인 형식입니다. `@page`가 종이 크기를 정하고, `.poster`의 안쪽 여백(위아래 30 mm, 좌우 38 mm)이 글자가 넘지 말아야 할 선입니다. 종이 끝까지 닿는 그림은 `.poster` 밖에 두어 넘침 검사에서 뺍니다. 플러그인이 있으면 그 스크립트로 뽑고 검사할 수 있습니다.

```bash
python poster/build.py v7 --html
node <make-poster>/scripts/render.mjs poster/v7/poster.html poster/v7/poster.pdf --preview poster/v7/poster.png --preview-width 1188
node <make-poster>/scripts/check-fit.mjs poster/v7/poster.html
```

## 다시 만들기

```bash
python poster/build.py
```

`LATEST`(6안)를 이 폴더 바로 아래에 만듭니다. 안 이름을 붙이면 그 안을 그 폴더에 만듭니다. 최종 8안은 `python poster/build.py v8`입니다.

```bash
python poster/build.py v4
```

Edge나 Chrome, 그리고 글꼴 Noto Sans KR이 있어야 합니다. 문구는 `build.py` 맨 위의 `TEXT`에서 고치며, 4안과 5안에 함께 들어갑니다. 6안도 글자는 모두 `TEXT`에서 가져오고, `v1/poster.svg`에서는 글자의 크기·굵기·자리만 씁니다. 한 줄 설명(`description`)은 6안과 7안이 씁니다. 7·8안은 `python poster/build.py v7`(또는 `v8`)로 Edge에서도 뽑을 수 있고, `--html`을 붙이면 `poster.html`만 씁니다.

## 4·5안 구성

1안처럼 컨베이어를 지평선 삼아 위는 남색 하늘, 아래는 산호 바닥 두 부분으로만 나눕니다. 상자·번호·구획 없이 그림과 글자만 둡니다.

| 부분 | 배경 | 내용 |
|---|---|---|
| 위 | 남색 | 학교·사업명, 그림 |
| 아래 | 산호 | 제목 두 줄, 한 줄 설명, 작동 과정·시스템 구성 두 칸, 학과·팀원 |

안마다 다른 것은 `LAYOUTS`의 값뿐입니다.

| | 4안 | 5안 |
|---|---|---|
| 하늘 : 바닥 | 약 56 : 44 (경계 471 mm) | 1 : 2 (경계 280 mm, 위 3분할선) |
| 그림 크기 | 원·장치 모두 1배 | 원 0.7배, 장치 0.82배. 하늘이 낮아 원은 하늘 띠에 맞추고, 장치는 덜 줄여 불량품이 보이게 했습니다 |
| 제목 | 58 mm | 72 mm. 둘째 줄이 아래 3분할선(561 mm)에 앉습니다 |
| 바닥에 비친 원 | 짧게 | 조금 길게. 너무 길면 줄무늬 그릇처럼 무거워 보입니다 |

5안은 세로 3분할에 맞춰 위 1/3에 하늘과 그림, 가운데 1/3에 비친 원과 제목, 아래 1/3에 한 줄 설명·작동 과정·시스템 구성과 학과·팀원이 놓입니다.

- 그림은 한 장면입니다. 왼쪽에서 부품이 들어오고, 가운데 검사 자리 바로 위에서 카메라가 내려다보고, 로봇팔이 그 자리의 불량품을 집어 올립니다. 오른쪽 앞의 불량 상자가 불량품이 갈 곳입니다.
- 원: 모든 원이 검사 자리 한 점에서 컨베이어에 닿습니다. 카메라가 살피는 자리이고, 가장 밝은 한가운데에 불량품이 있습니다. 카메라에서 그 자리로 점선 두 줄이 내려옵니다.
- 양품과 불량품: 양품은 모서리가 반듯한 밝은 크림색, 불량품만 남색이고 오른쪽 위 모서리가 깨져 산호색 금이 가 있습니다. 그리퍼 몸·손가락과 불량품 사이를 조금 띄워, 빛 속에서 불량품 모양이 따로 보이게 했습니다.
- 별은 빛 바깥 하늘에 몇 개만 흐리게 둡니다.
- 작동 과정은 [공정 순서](../docs/line-sequence.md)의 "부품마다 멈춤" 방식, 시스템 구성은 [API](../docs/API.md)와 [로봇팔 문서](../docs/robot-arm.md)를 따릅니다. 연결 방식(소켓 종류·USB 등)은 적지 않습니다. 이 문서들이 바뀌면 `TEXT`도 맞춰 고칩니다.
- 시스템 구성 칸은 검사 자리와 같은 세로선(가운데에서 조금 왼쪽)에서 시작합니다.

글자 색은 역할로 나눕니다.

| 역할 | 남색 위 | 산호 위 |
|---|---|---|
| 핵심 (학교, 제목, 한 줄 설명, 차례, 팀원) | 흰색 | 남색 |
| 보조 (사업명, "작동 과정"·"시스템 구성", 화살표) | 흐린 크림 `MUTED` | 흐린 남색 `INK_SOFT` |

## 색

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| 남색 | `#051230` | 하늘, 글자, 불량품 |
| 산호 | `#F48067` | 바닥, 빛의 가운데 고리 |
| 노을색 | 두 색을 섞은 여섯 단계 (`dusk()`) | 빛의 바깥 고리 |
| 밝은 산호 | 산호에 흰색을 섞은 색 | 빛의 가운데, 양품, 별 |
| 흐린 남색 | 남색에 산호를 섞은 색 (`INK_SOFT`) | 산호 위 보조 글자 |
| 학교 하늘색 | `#0095C8` (PANTONE 639 C) | Authority Mark. 학교 원본 색 그대로입니다. 남색 위에서 대비 5.4:1, 산호 위에서는 1.3:1이라 남색 하늘에 둡니다 |

`dusk()`의 `turn`이 섞는 방식을 정합니다. 0이면 두 색을 곧게 섞어 가운데가 탁한 갈색이 되고, 1이면 보라 쪽으로 돌아 더 몽환적이지만 보라가 세 번째 색처럼 보입니다. 지금 값은 그 가운데인 0.5입니다.

## 인쇄할 때

- 색은 RGB입니다. 인쇄소가 CMYK로 바꾸면 남색과 산호가 조금 달라질 수 있습니다.
- 재단 여유(도련)는 없습니다. 배경색이 종이 끝까지 닿습니다.
