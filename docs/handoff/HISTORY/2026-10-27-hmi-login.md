# 밖 주소 로그인: 공용 비밀번호, 원점 잡기만 로그인, 원점은 Worker 한 곳

## 요약
- 장비망 밖 주소(`hmi.hypefree.net`)의 화면 주소 Access를 대신할 로그인을 만들었다. 로그인하지 않아도 모든 기능을 쓰고, 로그인해야 하는 것은 원점 잡기뿐이다(D-023).
- Worker(`hmi-web-mockup/cloudflare/worker.js`)
  - `/auth/session` · `/auth/login` · `/auth/logout`: 비밀번호는 Worker 비밀값 `HMI_PASSWORD`, 쿠키 `hmi_session`은 `SESSION_KEY`로 서명만 하고 저장하지 않음(24시간, HttpOnly · Secure · SameSite=Strict). 비밀번호 비교는 HMAC 비교(`crypto.subtle.verify`). 로그인 시도는 IP마다 60초에 5번(`LOGIN_LIMIT`). 값을 바꾸는 요청은 JSON만 받고 `Sec-Fetch-Site`가 다른 사이트면 거절, 몸통 4KB 넘으면 읽지 않음.
  - `/home`: GET은 누구나, PUT은 로그인해야 함. KV `HOME`에 저장하고 각도는 ±360 안만, 저장 시각은 Worker 시계.
  - 브라우저 → 서버 메시지를 XML로 읽고 다시 써서 넘김(서버가 받는 글이 검사한 글과 같도록). 원점 복귀(`Home`)의 각도가 저장된 원점과 다르면 서버로 넘기지 않고 같은 id로 `Reply result="Rejected"`(`HomeMismatch`, 원점이 없으면 `HomeNotSet`). 이름의 대소문자 · 앞뒤 공백 · 다른 자리에 넣은 원점 복귀도 찾음. 읽지 못한 글 · 바이너리 · 64KB 넘는 글은 넘기지 않고 `Error`. 각도 없이 이름만 보낸 원점 복귀와 다른 명령은 그대로 넘김.
- 화면: `hmi-web-mockup/js/auth.js`(화면을 내준 곳이 `/auth/session`에 JSON으로 답하면 로그인이 있는 곳), `home.js`의 Worker 저장(`useRemote` · `refresh`), 아래 줄 "로그인" 키와 로그인 창(`react/src/LoginDialog.jsx`), 로그인하지 않고 원점 잡기를 누르면 로그인 창부터, 원점 복귀 · 자동 시작 전에 Worker의 원점을 다시 읽음. `xml-protocol.js`가 Worker의 거절 코드를 원점 문구로 읽음.
- 장비망 안 화면(`dev-server.py` 등)은 로그인이 없고 원점은 지금처럼 브라우저마다.
- 도구와 문서: `set-password.py`(비밀번호 10글자 이상, `SESSION_KEY`를 새로 만들어 함께 넣음 — 비밀번호를 바꾸면 모두 다시 로그인), `wrangler.jsonc`(`kv_namespaces` `HOME`은 id 없이, `ratelimits` `LOGIN_LIMIT`), docs/cloudflare.md(구조 · "로그인으로 바꾸기" 순서 · 안 될 때 · 제한), docs/xml-protocol.md 3장, hmi-web-mockup/README.md.
- 좁은 화면에서 아래 줄 키가 셋이 되며 1024px에서 "다크 모드"가 두 줄로 접히고, 360px에서 가로 스크롤이 생겨 고쳤다(키 이름은 접지 않고, 599px 이하에서는 장치 줄 아래로 내리고 키 안쪽 여백을 줄임).
- main까지 통합했고 배포하지 않았다. 지금 `hmi.hypefree.net`은 소스 41b79c8과 화면 주소 Access 그대로다.

  - 몸통 4KB 제한을 넣은 뒤 로그인 · 로그아웃을 다시 확인
- 직접: 장비망 안 화면(`dev-server.py 5173`, `?mock=0`)은 로그인 키가 없고 원점 잡기가 예전 확인 창으로 브라우저에 저장됨 (2026-10-27)

## 시도했다가 버린 방법
- 화면 버튼만 막기 → 화면 주소를 아는 사람은 웹소켓에 직접 붙어 아무 각도의 원점 복귀를 보낼 수 있고, 서버는 원점 각도의 범위를 보지 않음 (직접 2026-10-27 · worker.js 중계 구조, CURRENT 공백 "서버가 `Home` 각도의 범위를 검사하지 않음") → Worker에서 원점 저장과 원점 복귀 각도를 검사 (사용자 선택)
- 원점을 지금처럼 브라우저마다 두기 → 로그인한 적 없는 브라우저에는 원점이 없어 원점 복귀를 못 하고, Worker가 각도를 견줄 기준이 없음 → Worker(KV) 한 곳에 저장 (사용자 선택, D-023)
- Worker가 원점 복귀 각도를 저장된 원점으로 바꿔 넘기기 → 화면이 모르는 사이 명령이 바뀜 → 다르면 넘기지 않고 같은 id로 거절해 화면이 이유를 보이게 함
- 로그인 실패 횟수를 KV에 세기 → KV 쓰기 한도(무료 하루 1,000번, Cloudflare KV 한도 문서)를 공격으로 다 쓰면 원점 저장까지 막힘 → Workers Rate Limiting 바인딩 + 비밀번호 10글자 이상

## 남은 공백·다음
- 배포 전. 순서는 docs/cloudflare.md "로그인으로 바꾸기": 배포(KV가 이때 만들어짐) → `set-password.py` → Access가 있는 채로 로그인 · 원점 확인 → 화면 주소 Access 앱만 지움(터널 주소 앱은 그대로) → 시크릿 창으로 확인 → 로그인한 사람이 원점 잡기를 한 번 함(전에 브라우저에 저장한 원점은 쓰지 않음)
- 로그인 시도 제한 바인딩이 무료 플랜에서 되는지 문서로 확정하지 못함(Rate Limiting 문서 · 가격 문서 · GA 공지 모두 플랜을 적지 않음). 첫 배포에서 확인
- 화면 주소가 공개되면 서버 담당 README의 밖 연결 제한 권고와 달라 서버 담당에게 알려야 함
- `wrangler dev`를 다시 켜는 순간 `Uncaught Error: Network connection lost`가 한 번 기록됨. 그 뒤 새로 고침과 곧바로 끊은 웹소켓 여섯 개로는 다시 나오지 않음 (직접 2026-10-27)
- 이 PC의 `hmi-web-mockup/cloudflare/.dev.vars`(git이 무시)에 시험용 `HMI_PASSWORD` · `SESSION_KEY` 두 줄을 더했다(값은 `.dev.vars.example`의 시험용 값). 이 PC 시험용이고 배포에는 쓰이지 않음
