# 장비망 밖 주소는 Access 대신 로그인, 로그인은 원점 잡기에만 (D-023 추가, D-006 · D-017 수정)

## 요약
- 사용자가 화면 주소의 접근 제한(Cloudflare Access)을 풀고 로그인을 만들기로 했다. 로그인하지 않아도 모든 기능이 되어야 하고, 로그인으로 바뀌는 것은 값을 바꿀 수 있는지다.
- 질문으로 정한 것
  - 로그인 방식: 공용 비밀번호 하나 (다른 선택지: 이메일 일회용 코드, Firebase 로그인)
  - 로그인해야 쓰는 조작: 원점 잡기만 (시작 · 정지 · 원점 복귀, 운전 모드 · 옮길 부품, 긴급정지 · 해제는 로그인 없이)
  - 막는 곳: Worker (화면 버튼만 막는 안은 고르지 않음)
  - 적용 범위: 밖 주소만 (장비망 안 화면은 지금처럼 로그인 없이)
  - 밖 주소의 원점: Worker에 하나로 저장 (지금처럼 브라우저마다 두는 안은 고르지 않음)
- D-023을 새로 두고, D-006(로그인 없음)과 D-017(화면 주소 앞 Access)을 고쳤다. D-014(원점은 서버가 아니라 HMI 쪽)는 그대로다 — Worker는 HMI를 내주는 쪽이다.

## 결정 변경
- D-006 이전 본문: "로그인은 두지 않는다. 문구는 한국어만 쓰되 영어를 추가할 수 있는 구조로 둔다. 노트북·데스크톱을 우선으로 하되 다른 화면 크기에서도 깨지지 않게 한다." (사용자 2026-10-06) → 로그인은 장비망 밖 주소에만 두고 원점 잡기만 바뀐다(D-023). 나머지는 그대로
- D-017 이전 본문의 "앞에 Cloudflare Access(허락한 사람만)를 둔다" (사용자 2026-10-17) → 화면 주소 앞에는 Access를 두지 않고 로그인(D-023)을 쓰며, 터널 주소 앞의 Access(서비스 토큰만)는 그대로 둔다
- D-023 추가: 장비망 밖 주소의 로그인은 원점 잡기에만 쓴다 (본문은 DECISIONS)

## 근거
- 사용자: "현재 파이어베이스 인증을 기반으로 접근을 허락하고 있는데 이걸 풀어버리는 대신, 로그인을 만들꺼야. 단 로그인을 안해도 모든 기능은 다 작동해야하고 로그인으로 변경되는건 값을 수정할수 있는가에 대한 부분이야." (대화, 2026-10-27)
- 사용자: 질문 답 — "공용 비밀번호 하나", "원점 잡기", "Worker에서 막음", "밖 주소만", "Worker에 하나로 저장" (대화, 2026-10-27)
- 직접: 저장소에 Firebase는 없고 지금 화면 주소를 막는 것은 Cloudflare Access라, 그것을 푸는 이야기로 확인하며 질문함 (2026-10-27)

## 남은 공백·다음
