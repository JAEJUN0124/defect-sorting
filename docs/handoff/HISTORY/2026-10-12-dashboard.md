# 대시보드(감시 화면) v1~v2 — frontend-design 설계, anti-slop 검수, 심플함 평가

## 요약
- 사용자 요청으로 두 번째 화면인 대시보드(`hmi-web-mockup/dashboard.html`)를 만들었다. 조작 화면 때와 같은 과정이다: frontend-design으로 설계 → v1 → 측정 → anti-slop 검수 → v2 → 측정.
- 조작 화면의 디자인 체계(제어함 회색 판, IEC 60073 신호색만, 그림자·그라디언트 0, 글자 4단계 14·16·21·36px, 4px 간격, 긴급정지만 대담하게)를 이어받았다. 공통 값은 `hmi-web-mockup/css/base.css`로 뺐다.
- 보여 주는 것: 윗판(상태 → 긴급정지 → 계수기, 가동 시간), 카메라 2대, 분당 판정 막대(최근 30분), 최근 판정, 로봇팔·리더암 서보 6개씩(위치·온도 지시계·부하)과 팔마다 전원 전압, 최근 경보, 장치 연결. 누를 수 있는 것은 긴급정지·조작 화면으로 가기·다크 모드뿐이다.
- anti-slop 기준(S1~S15) 위반은 0건이었고, 장식·구조 문제 3건을 v2에서 고쳤다: 서보 위치 지시계 12개 삭제, 서버 끊김 때 본문을 흐리게 하던 것 대신 "화면 값은 몇 시 기준" 안내, "말 — 조각" 문장 2종을 문장으로.
- 확인하면서 배치 문제 3건도 고쳤다: 스크린 리더용 표가 높이를 차지해 세로 스크롤이 생김, 경보 6줄일 때 900px을 넘음(칸 사이 24→16px, 표 줄 28→24px, 경보 5줄), 카메라 한 대인 서버에서 카메라가 전체 폭으로 커짐(카메라 칸 수 고정).
- 조작 화면에는 "대시보드" 버튼을 더했다. 두 화면은 가짜 서버 여부·주소 같은 설정을 주소로 넘긴다.
- v1은 docs/v1-snapshot/dashboard.v1.html·dashboard.v1.css에 남겼고, 평가는 docs/simplicity-report.md 10장에 썼다.

## 시도했다가 버린 방법
- 서버 끊김 때 본문을 흐리게(불투명 0.6) → 글자 대비가 4.5:1 아래로 떨어짐 (직접 2026-10-12 · 측정 도구) → 흐리지 않고 윗판에 "화면 값은 몇 시 기준" 안내
- 스크린 리더용 표에 바로 `sr-only` → 표에는 overflow가 듣지 않아 문서 높이 1,487px (직접 2026-10-12 · 미리보기 브라우저) → 표를 감싸는 칸을 숨김
- 라이트 테마 불량 막대에 IEC 노랑 #F2B705 → 바탕 대비 1.52:1 (직접 2026-10-12 · validate_palette) → 같은 계열 짙은 단계 #A67C00
- 서보 위치를 ±180° 지시계로 표시 → 정상 범위가 없어 판단에 쓰이지 않는 장식 (직접 2026-10-12 · anti-slop 검수) → 숫자만, 지시계는 온도·전원에만
