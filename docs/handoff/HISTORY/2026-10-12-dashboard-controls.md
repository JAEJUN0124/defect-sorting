# 두 대시보드에 조작 기능 — 공용 조작 모듈, 다시 설계, 화면별 공유 사본

## 요약
- D-013에 따라 첫 대시보드(`hmi-web-mockup/dashboard.html`)와 탭 대시보드(`hmi-web-mockup/dashboard-tabs.html`)에 조작 화면의 조작(F-01~F-06: 시작/정지, 긴급정지와 해제, 프로그램 종료, 원점 잡기, 카메라 켜기/끄기, 운전 모드)을 모두 넣었다. 그전까지 대시보드는 보기 전용이었다.
- 조작은 새 공용 파일 `hmi-web-mockup/js/controls.js`가 조작 화면(`js/app.js`)과 같은 규칙으로 보낸다. 원점·운전 모드는 정지 상태에서만(D-003), 긴급정지 해제는 확인 창을 거치고 해제 뒤에도 정지(D-004), 원점 각도는 `config/home-position.js`(D-007). 실패하면 이유를 그 단추 곁과 윗판에 쓴다. 단추는 `data-ctl` 속성으로 찾으므로 한 기능의 단추가 여러 자리에 있어도 된다. 조작 화면 파일(`index.html`, `js/app.js`, `css/hmi.css`)은 바꾸지 않았다.
- 처음 넣은 모양(첫 대시보드는 맨 아래 줄 작은 키 묶음, 탭 대시보드는 같은 크기 판 6개의 조작 탭)에 사용자가 "이게 최선이야? 다시"라고 해, frontend-design으로 다시 설계하고 anti-slop으로 검수했다.
  - 첫 대시보드: 윗판 2단. 1단은 계기(상태·긴급정지·계수기 6개), 2단은 조작(운전 모드 → 시작/정지 → 원점 잡기·안내·프로그램 종료). 시작/정지는 긴급정지 바로 아래 같은 폭이고, 긴급정지 중에는 그 자리에 "긴급정지 해제"가 뜬다. 자리를 내느라 분당 판정 그림을 120→96px, 최근 판정·최근 경보를 5→4줄로 줄였다.
  - 탭 대시보드: 윗판 긴급정지 옆에 시작/정지(긴급정지 중에는 "해제")를 두고 계수기는 4개로 줄였다. 운전 묶음에 조작 탭을 더했다. 큰 운전 판에 운전 모드 → 시작 조건 → 시작과 정지, 아랫줄에 원점(원점 각도와 지금 각도)·카메라·긴급정지와 종료.
  - 시작 조건은 서버가 시작을 거절하는 이유(docs/API.md 4.1장)와 같은 목록이다: 서버 연결·긴급정지·고장·전원 전압, 컨베이어·로봇팔·주 카메라·(수동이면) 리더암. 막힌 것이 있으면 할 일을 한 줄로 쓰고, 아직 모르는 것은 회색 "확인 불가"로 둔다.
  - 카메라마다 꺼져 있으면 가운데 "카메라 연결", 켜져 있으면 오른쪽 위 "카메라 끄기"(조작 화면과 같은 자리). 탭 시안 v2의 "조작 화면 열기" 단추는 이것으로 바뀌었다.
- anti-slop: S1~S15 위반 0건, 장식·위계 3건을 고쳤다(모르는 시작 조건을 노랑으로 칠하던 것, 원점 판의 설정 파일 이름 중복, 묶음 카메라 키가 카메라별 키보다 큰 것). 설계와 측정은 docs/simplicity-report.md 11.4장, 화면 설명은 hmi-web-mockup/README.md.
- 공유용 사본: 처음에는 탭 대시보드에 조작 화면을 함께 넣어 한 페이지로 올렸다가, 사용자 지적으로 화면마다 따로 올렸다(D-013). 모두 claude.ai 비공개 페이지다.
  - 조작 화면: https://claude.ai/artifact/J2JcnwrykNKN2XvVS9bJFf
  - 첫 대시보드: https://claude.ai/artifact/3wD84fi1x5QXtcMBv7LUjC
  - 탭 대시보드: https://claude.ai/artifact/Gf1QCNNZktCwp4iP3mj5GH
  - 저장소 파일과 다른 점: 다른 화면으로 가는 단추를 숨김, 가짜 서버를 화면마다 따로 돌림. 대시보드 사본은 처음에 열자마자 라인이 돌게 했다가, 대시보드에도 시작이 생겨 저장소처럼 정지 상태로 열리게 바꿨다.
  - 조작 화면 사본은 이번 조작 작업 전에 올렸다(조작 화면 파일은 그 뒤 바꾸지 않음). 사본을 만든 스크립트는 저장소 밖 임시 폴더에 있어 남지 않는다.
- 사용자 지시로 작업 브랜치 커밋 d52c539를 main에 fast-forward로 합쳤다.

## 시도했다가 버린 방법
- 확인 창의 답을 `close` 이벤트로 받음 → 화면을 그리지 않는 동안(숨은 창)에는 `close`가 늦게 와 앞 창의 `close`가 다음에 연 창을 취소함 (직접 2026-10-12 · 미리보기 브라우저) → 확인·취소 단추를 누른 순간과 Esc(`cancel` 이벤트)로 답을 정함
- 첫 대시보드의 원점·운전 모드·종료를 맨 아래 줄 작은 키로 → 덧붙인 티가 남 (사용자 2026-10-12 · "이게 최선이야? 다시") → 윗판 2단 조작 줄
- 탭 대시보드 조작 탭을 같은 크기 판 6개로 → 위계가 없고 판마다 빈자리가 커 설정 화면처럼 보임 (사용자 2026-10-12 · 같은 지적) → 운전 순서대로 놓은 운전 판 하나와 아랫줄 판 셋
- 시작 조건에서 아직 모르는 것까지 노란 "!"로 칠함 → 서버가 끊기면 7개가 모두 경고 (직접 2026-10-12 · anti-slop 검수) → 모르는 것은 회색 "확인 불가", 노랑은 실제로 막힌 것만
- 공유용 사본에 조작 화면을 함께 넣고 "조작 화면" 단추로 이음 → 사용자가 화면마다 따로 만들라고 함 (사용자 2026-10-12) → 화면마다 따로 올리고 이동 단추를 숨김
