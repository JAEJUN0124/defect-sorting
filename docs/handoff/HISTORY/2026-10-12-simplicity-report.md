# 심플함 정량 비교 보고서와 측정 도구

## 요약
- 사용자 요청(애플 감성을 베끼지 말고 수치화해 비교)에 따라 Apple HIG 원칙을 15개 지표로 바꿔 화면을 재는 도구 `hmi-web-mockup/tools/simplicity-audit.js`를 만들고, 결과를 docs/simplicity-report.md에 정리했다.
- 결과: 라이트 v1 96·99·99 → v2 100·100·100 → v3 99·99·98(카메라 확대로 여백만 줄어듦), 다크 100·99·98·99, Apple Music 웹(다크) 실측 75(공통 14개 지표).
- Apple 실제 화면과 수치가 같거나 가까운 지표는 14개 중 4~5개였다. 원칙은 따르되 겉모양은 닮지 않았다는 근거로 썼다.

## 근거
- 사용자: 수치 비교 요청 (대화, 2026-10-06)
- 직접: 1440×900 배포 화면(`?dev=0`)에서 장면 A 초기·B 가동(불량 이벤트 1건 주입)·C 긴급정지·D 로그 창을 같은 도구로 측정 (미리보기 브라우저, 2026-10-06~07)
- 직접: Apple HIG 원문(buttons, accessibility, typography, color, layout, dark-mode) 확인 (developer.apple.com, 2026-10-06~07)
- 직접: Apple Music 웹(music.apple.com/kr/new)을 같은 도구로 측정 (미리보기 브라우저, 2026-10-06~07)

## 시도했다가 버린 방법
- 색 전환 효과가 도는 채로 재기 → 숨겨진 탭에서 전환이 멈춰 중간 색이 잡힘 (직접 2026-10-06) → 재는 동안 전환·애니메이션을 끔
- 색 계열을 30° 고정 구간으로 세기 → 노랑과 짙은 노랑 글자가 경계에 걸려 다른 계열로 셈 (직접 2026-10-06) → 계열 첫 색에서 25° 안쪽을 한 계열로 묶음
- 바깥 여백(margin) 값을 모두 간격으로 세기 → `margin: auto`가 큰 px 값으로 잡혀 격자 위반으로 셈 (직접 2026-10-06) → 96px 초과 값은 제외
- 배경색을 body까지만 찾기 → html에 배경이 있는 페이지(Apple Music)에서 흰색으로 오판 (직접 2026-10-06) → html까지 찾음
- 모든 글자를 대비 검사 → 투명한 스크린 리더용 글자와 앨범 사진 위 글자를 오판 (직접 2026-10-06) → 둘 다 제외하고, 반투명 글자색은 배경과 섞어 계산

## 남은 제한
- 2·6·7·13·14번 지표는 HIG에 숫자가 없어 관찰로 정한 기준이다.
- 다크 첫 화면의 여백 84.9%는 검은 카메라 화면이 바탕과 대비 1.5 미만이라 빈 곳으로 잡힌 도구 한계다.
- Apple 기준점은 웹 페이지 한 장(음악 앱)이다.
