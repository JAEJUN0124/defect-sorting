# HMI↔서버 통신을 소켓 + XML로 바꿈 (D-002 수정)

## 요약
- 사용자가 서버 담당과 이야기한 결과를 알려 줌: 통신은 소켓, 데이터는 XML. 서버→HMI는 카메라 화면, 장비(컨베이어), 로봇팔(통신 상태), 검사 데이터. HMI→서버는 긴급정지·시작·종료·원점 잡기·자동/수동 전환.
- HMI가 쓰는데 빠진 것을 알려 줌: 라인 상태, 명령 결과, 원점·종료 완료 알림, 리더암, heartbeat, 경보 기록, 긴급정지 해제, 일반 정지, 카메라 켜기/끄기, 연결 직후 전체 상태. 사용자는 "명령 결과는 리플라이로 쏴준대", 나머지도 "다 해준다고 하네"라고 답함.
- 장비 데이터는 연결 상태와 멈춘 이유가 꼭 필요하고 공정 단계는 있으면 좋다고 정리해 줌. 장치 연결 상태를 한 메시지에 모으는 XML 예시를 보임 (형식은 미정).
- D-002 이전 본문: "명령(시작·정지·긴급정지·원점·모드·카메라·종료)은 HTTP REST로 보내고, 상태·판정·이벤트는 WebSocket으로 받는다." (사용자 2026-10-06)

## 근거
- 사용자: "소캣으로 통신, 데이터는 xml로 한대" 와 보낼 데이터 목록 (대화, 2026-10-13)
- 사용자: "명령 결과는 리플라이 쏴준대. 나머지는 다 ㄱㅊ을듯? 이야기 해 보니까 다 해준다고 하네" (대화, 2026-10-13)
- 직접: HMI는 WebSocket·Socket.IO·SSE·폴링은 받지만 메시지를 JSON으로만 읽고, JSON이 아니면 버린다 (`hmi-web-mockup/js/adapter.js`, `js/transport.js` 확인, 2026-10-13)

## 남은 공백·다음
- 소켓 종류(WebSocket·TCP) 미확인. 브라우저는 TCP에 직접 붙지 못한다.
- XML 형식 미정. HMI에 XML 읽기·보내기를 붙이지 않음. docs/API.md는 아직 HTTP·JSON 기준.
- 카메라 영상은 XML에 넣지 말고 따로(MJPEG) 받자고 제안했으나 답은 받지 않음.
- 다음: 소켓 종류와 XML 형식이 정해지면 API 문서와 HMI를 맞춤.
