# API v0.3과 서버↔컨베이어·로봇팔 규약 초안, 가짜 서버 공정 순서

## 요약
- 사용자 요청: 지금 구조에서 가능한 API를 설계하고, 로봇팔·컨베이어 벨트와 주고받는 과정의 API도 만든다. HMI↔서버 쪽은 에이전트가 기록 조회를 1순위로 추천했고, 장치 쪽은 사용자 답(근거)에 맞춰 정해지지 않은 부분을 비워 두거나 두 방식이 모두 되게 설계했다.
- 새 문서 세 개
  - docs/conveyor-protocol.md: 서버 ↔ 아두이노 컨베이어 USB 시리얼 규약 v1. 115200bps 한 줄 글자, 명령(`INFO`·`STATUS`·`RUN`·`STOP`·`HALT`·`RESET`·`SPEED`·`AUTOSTOP`·`PING`), 응답(`OK`·`ERR`), 알림(`!READY`·`!STATE`·`!PART`). 아두이노가 `INFO`로 가진 기능(속도 조절·센서·스스로 멈추기·정지 단추·감시 시간)을 알리는 일반형이다. 가동 중 감시 시간(기본 1000ms) 동안 줄을 못 받으면 스스로 멈추고 잠그며(`halted`), 잠금은 `RESET`으로만 푼다.
  - docs/arm-control.md: 공정 제어가 로봇팔에 시키는 동작 단위(`run_task`·`move_home`·`stop`·`relax`·`teleop` 등)와, 작업 = 단계 목록(`pose`·`gripper`·`policy`·`wait`·`check`). 자세와 학습 정책을 섞은 예, 다시 시도, 쥐었는지 판단, 움직임 규칙(보간·관절 한계·LeRobot `max_relative_target`), 멈출 때 표.
  - docs/line-sequence.md: 부품마다 멈추는 공정 순서(`feeding` → `inspecting` → `sorting`·`passing`), 시간 제한·고장과 풀리는 방법, 계속 도는 다른 안, 수동 모드 초안, HMI 명령별 장치 동작, 설정값 초안.
- docs/API.md v0.3 (모두 더한 것): 기록 조회 `GET /api/history`와 판정·이벤트 순번 `seq`(`run_id`·`now`·`last_seq`), 상태 `cycle`·`home_required`, `fault.clear`(`auto`·`home`·`start`), 시작 거절 `409 HOME_REQUIRED`, 고장 코드 `GRIP_FAILED`·`ARM_MOTION_TIMEOUT`·`CONVEYOR_HALTED`·`PART_STUCK`·`INSPECTION_TIMEOUT`, 이벤트 `sort_retry`·`conveyor_halted`. docs/server-cases.md 15·16장과 docs/robot-arm.md 설치 순서·장치 점검 설명도 고쳤다.
- 코드
  - `hmi-web-mockup/js/conveyor.js`(새 파일): 규약의 서버 쪽 견본(명령을 하나씩, `PING`, 응답 없음 3번 → 끊김), 가짜 아두이노(벨트 위 부품·센서), 규약 점검.
  - `js/mock-server.js`: 가짜 아두이노를 규약 그대로 써서 부품마다 멈추는 공정 순서로 돌고, 불량품은 로봇팔 작업(자세 → 학습 정책 흉내 → 자세)으로 옮긴다. 기록 조회, 원점 필요, 고장 풀림, 흉내(집기 실패·부품 걸림·컨베이어 정지 단추)를 더했다. `js/mock-hub.js`는 탭이 가짜 서버를 넘겨받을 때 기록·순번·`run_id`도 잇는다.
  - 화면: `js/store.js`가 화면을 열 때와 다시 연결될 때 기록을 묻고 순번으로 겹침을 거른다. 세 화면에 원점 필요·고장 풀림 안내와 로그를 시각 차례로 끼우기, 탭 대시보드에 공정 흐름의 지금 단계 칸 표시와 시작 조건 "원점", 가짜 카메라 영상이 단계를 따라 검사선에 멈춤.
  - 도구: `tools/devices.html`에 컨베이어 규약 점검 칸과 로봇팔 자세 저장, `tools/server-check.html`에 기록 조회·순번·공정 단계 확인. `.claude/launch.json`에 변형 서버 설정을 더했다.

## 경위
- HMI 쪽 진단: v0.2는 지금 순간(명령·상태·실시간)만 다뤄, 지난 기록이 화면마다 브라우저에만 쌓였다(최근 판정 60·분당 120분·로그 200). 새로고침하거나 나중에 연 화면, 다시 연결된 화면에서 기록이 비어 기록 조회를 1순위로 추천했다. 화면끼리 경보 확인을 나누는 것과 설정 API는 넣지 않았다(설정 API는 원점 각도를 HMI 파일에 두는 D-007과 겹침).
- 기록 조회 판단: 이벤트·판정에 한 줄로 잇는 순번 `seq`를 매기고, 서버를 다시 켜면 바뀌는 `run_id`로 순번이 처음부터인 것을 알아챈다. 분당 집계는 서버 시각(`now`)과 이 PC 시각의 차이를 빼서 옮기되 5초 안쪽은 같은 시계로 보고, `last_seq`까지는 서버 집계에 들어간 것으로 보아 두 번 세지 않는다. 처음 채우는 기록은 알림 점을 켜지 않고, 다시 연결 때 채우는 기록은 켠다. 기록을 묻는 동안 실시간 판정·이벤트는 최대 2초 줄 세운다. 실시간 연결이 없는 서버(`push: 'poll'`)면 2초마다 기록을 묻는다.
- 안전 판단: 화면 긴급정지 때 로봇팔은 힘 빼기를 초안으로 했다(아래 버린 방법). 그래서 긴급정지·로봇팔 고장 뒤에는 자세를 알 수 없어 원점을 다시 잡아야 시작하게 했다(`home_required`, `409 HOME_REQUIRED`). D-004(해제 뒤 정지 유지)와 함께 쓰인다. 가짜 서버는 원점 자세로 켜진다고 보고 처음에는 `home_required`를 false로 둔다.
- 고장이 풀리는 방법을 `auto`(원인이 사라지면)·`home`(원점 잡기)·`start`(확인하고 시작)로 나눠, 집기 실패처럼 원인이 남지 않는 고장도 화면이 할 일을 안내하게 했다.
- 수동 모드는 초안으로 컨베이어를 부품마다 세우지 않고 판정만 보낸다(다시 가동하라는 신호가 따로 없어서). 정할 것으로 남겼다.

## 시도했다가 버린 방법
- 기록 조회 경로를 `/api/events`로 → `hmi-web-mockup/js/config.js`의 `server.sseUrl` 기본값이고 변형 서버의 SSE 주소와 겹침 (직접 2026-10-12 · config.js, variant-server.py) → `/api/history`
- 화면 긴급정지 때 로봇팔을 그 자리에서 버티게(힘 유지, 대화 중 에이전트가 처음 제안) → 끼였을 때 풀리지 않고, DC 전원을 뽑는 하드웨어 비상정지와 결과가 다르며, IEC 60204-1은 비상정지를 정지 범주 0·1로 둠 (직접 2026-10-12 · 에이전트 설계 검토, 기존 가짜 서버도 힘 빼기) → 힘 빼기를 초안으로 두고 팀이 정할 것으로 남김
- `PING`을 늘 250ms마다 → 감시 시간이 그보다 짧은 컨베이어(시험의 200ms)에서 감시 타이머가 걸림 (직접 2026-10-12 · node --test 실패) → 감시 시간의 1/4과 250ms 중 짧은 쪽
- 장치 점검의 주고받은 줄 기록에 `PING`과 그 `OK`도 남김 → 0.25초마다 쌓여 중요한 줄이 묻힘 (직접 2026-10-12 · 미리보기 브라우저) → 살아 있음 신호는 기록에서 뺌
- 다시 연결 때 채운 로그를 맨 위에 붙임 → "서버에 다시 연결했습니다" 줄보다 위로 가 시간 차례가 어긋남 (직접 2026-10-12 · 미리보기 브라우저) → 세 화면 모두 시각 차례로 끼움
- 기록 조회로 채운 판정도 하나씩 판정 알림으로 보냄 → 가짜 카메라 영상에 예전 판정 상자가 그려질 수 있음 (직접 2026-10-12 · 코드 검토) → 기록은 한 번의 기록 채움 알림으로 보내고 목록·그래프만 다시 그림
- Git for Windows bash의 `sed -i`로 코드 고치기 → CRLF 파일이 LF로 바뀌고 heredoc으로 덧붙인 줄과 섞임 (직접 2026-10-12 · 줄바꿈 수 확인) → 바꾼 파일을 작업 폴더의 CRLF로 다시 맞춤

## 남은 공백·다음
- 실제 아두이노·키트·서버로는 시험하지 않았다. 컨베이어 규약은 가짜 아두이노로만, 로봇팔 작업은 가짜 서버의 흉내로만 확인했다.
- 장치 쪽 초안 규칙(긴급정지 때 힘 빼기, 원점 필요, `clear` 세 가지, 수동 모드의 컨베이어, 정지 때 작업 마치기)은 팀이 정하지 않았다.
- 판정 시간 초과(`INSPECTION_TIMEOUT`)와 계속 도는 운전은 문서에만 있고 가짜 서버는 흉내 내지 않는다.
- 공유용 사본 3개는 이번 변경을 담지 않았다(다시 올리지 않음).
- 다음: 하드웨어 담당·서버 담당과 각 문서의 "정할 것" 합의, 아두이노 스케치가 생기면 장치 점검의 컨베이어 규약 점검
