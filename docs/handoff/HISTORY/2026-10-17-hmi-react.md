# 조작 화면을 React로 옮기고 메인 서버에서 띄울 준비

## 요약
- 조작 화면을 React 19 + Vite 8로 다시 만들었다 (`hmi-web-mockup/react/`). 설정·문구·XML·서버 연결·상태 모으기·원점·카메라 코드(`hmi-web-mockup/js/`)는 `react/src/legacy.js`가 예전 순서대로 불러 그대로 쓴다. 화면의 구조·class·id·문구는 React 전 조작 화면과 같고, 대시보드로 가는 단추만 없다.
- 대시보드 두 개(HTML·JS·CSS 7개 파일), React 전 조작 화면(`index.html`·`js/app.js`), 가짜 카메라 영상(`js/camera-sim.js`)을 지웠다. 그 화면들만 쓰던 문구 320개와 계기·차트 색 토큰도 지웠다. 가짜 서버에서 카메라를 연결하면 영상 대신 "가짜 서버에는 카메라 영상이 없습니다" 안내가 나온다.
- 빌드한 화면은 가짜 서버를 끄고 자기를 내준 서버의 `/ws/hmi`에 붙는다 (`react/src/server-defaults.js`). 개발 서버(`npm --prefix hmi-web-mockup/react run dev`, 5174, 미리보기 설정 `hmi-react`)는 가짜 서버가 기본이다.
- 메인 서버에 올리기: `hmi-web-mockup/tools/make-server-bundle.py`가 React를 빌드해 `wwwroot/`(조작 화면 + 서버 점검·장치 점검 페이지)와 `README-server.md`를 묶는다. 서버 쪽 할 일은 `app.UseDefaultFiles(); app.UseStaticFiles();` 두 줄과 `/`의 안내 글 빼기다 (답장 0.1). 점검 페이지용 설정은 `wsUrl: 'auto'`(화면을 내준 서버의 `/ws/hmi`, https면 wss)로 바뀐다.
- 다른 PC에서 열기: `hmi-web-mockup/tools/dev-server.py`가 메인 서버 묶음과 같은 배치(`/`는 `react/dist`, 그 밖은 `hmi-web-mockup` 파일)로 내준다. `--host 0.0.0.0`(8080)으로 띄우면 다른 PC가 같은 주소로 들어온다. React 전 화면으로 다른 PC에서 실제 서버에 붙는 것을 사용자가 확인했고, 같은 주소가 지금은 React 화면을 보여 준다.
- 기술 판단: 다른 PC용 서버는 Vite 개발 서버 대신 파이썬 `dev-server.py`로 빌드 결과를 내준다. 다른 PC에서 이미 접속되던 파이썬 서버를 그대로 쓰고(Node로 바꾸면 Windows 방화벽 허용이 다시 필요할 수 있음), 개발 서버를 장비망에 열지 않기 위해서다.
- 커밋 a8b9b3b(메인 서버에 올릴 준비·다른 PC에서 열기), 0e283d8(React 전환), 12b2b33(답장을 React 기준으로)을 main에 fast-forward로 합쳤다.

## 남은 제한
- 조작 화면은 모듈 스크립트라 파일 더블클릭으로는 열리지 않는다. 다른 PC용 주소와 메인 서버는 빌드한 `react/dist`를 내주므로 화면을 고친 뒤에는 `npm run build`를 다시 해야 한다.
- 브랜치를 바꾸면 Vite 개발 서버가 설정 파일(`vite.config.js`)이 잠깐 없어진 것을 보고 설정 없이 다시 떠 5173으로 옮겨 갔다 (직접 2026-10-17). 그때는 개발 서버를 다시 띄운다.
- 서보 과열·전압 이상·집기 실패 같은 흉내는 가짜 서버(`js/mock-server.js`)에 남아 있지만 누르는 단추는 대시보드와 함께 없어졌다 (시험에서만 씀).

## 남은 공백·다음
- 실제 서버에서 React 화면의 버튼은 아직 누르지 않았다.
- 답장과 메인 서버용 묶음은 아직 보내지 않았다 (사용자가 멈춤). 보낼 때 묶음을 새로 만든다.
- 다음: 사용자가 보내라고 하면 묶음을 새로 만들어 답장과 함께 서버 담당에게 전하고, 메인 서버에 올린 화면으로 확인한다.
