# 서버 ↔ 로봇팔 제어 약속 (초안)

서버의 공정 제어(부품 하나를 처리하는 순서)가 로봇팔에 무엇을 시키고 무엇을 돌려받는지 정리합니다.
로봇팔과 PC 사이의 통신 자체(Feetech 서보 규약)는 이미 정해져 있고 LeRobot이 처리하므로 새로 만들 것이 없습니다 ([로봇팔 문서](robot-arm.md)).
여기서 정하는 것은 그 위의 **동작 단위**입니다: 불량품을 집어 불량 상자에 넣기, 원점으로 가기(원점 복귀), 멈추기, 리더암 따라가기.
원점은 HMI가 저장합니다 (사용자 2026-10-14) — "원점 잡기"는 HMI 안에서 끝나고, 원점 복귀 명령이 그 각도를 서버에 가져옵니다 ([xml-protocol.md 3장](xml-protocol.md#3-원점--hmi가-저장-사용자-2026-10-14)).

자동 모드에서 팔을 움직이는 방법은 정해 둔 자세로 옮기기와 학습한 정책(LeRobot ACT 등)을 **섞어 쓸 가능성이 높습니다.**
그래서 작업을 단계 목록으로 적고, 단계마다 자세·그리퍼·정책 중 하나를 고르게 했습니다.

## 1. 나누는 법

```text
HMI ──(API.md)──> 서버 ─ 공정 제어 (line-sequence.md) ─┬─ 컨베이어 (conveyor-protocol.md)
                                                         ├─ 카메라·판정
                                                         └─ 로봇팔 제어 (이 문서) ─ LeRobot ─ 서보
```

- 로봇팔 제어는 서버와 **같은 파이썬 프로그램 안의 모듈**로 두기를 권합니다. LeRobot이 파이썬이고, 서보 포트와 카메라는 한 프로그램만 열 수 있기 때문입니다.
- 공정 제어는 아래 함수만 부르고 서보·LeRobot을 직접 만지지 않습니다. 그래야 팔을 움직이는 방법(자세·정책)을 바꿔도 공정 제어는 그대로입니다.

## 2. 로봇팔 제어가 내놓는 것

파이썬 이름은 예시입니다. 이름은 바꿔도 되지만 하는 일과 돌려주는 값은 맞춰 주세요.

| 함수 | 하는 일 | 돌려주는 것 |
|---|---|---|
| `connect()` | 로봇팔(팔로워)·리더암 연결, 캘리브레이션과 설정 파일 확인 | 없음. 캘리브레이션이 없으면 `CALIBRATION_REQUIRED` |
| `run_task(name, part_id)` | 작업 하나를 끝까지 함 (3장) | 작업 결과 (4장) |
| `move_home(angles)` | HMI가 보낸 원점 각도로 천천히 옮김 (F-04 원점 복귀 — 자동 모드·정지 상태) | 작업 결과 |
| `stop()` | 하던 작업을 지금 단계에서 끊고 그 자리에서 멈춤 (힘 유지) | 없음 |
| `relax()` | 힘 빼기 (긴급정지) | 없음 |
| `teleop(on)` | 수동 모드: 리더암 자세를 따라감 | 없음 |
| `telemetry()` | 서보 6개씩 위치·온도·전압·부하·전류·상태 비트 | API.md의 `telemetry`와 같은 값 |
| `holding()` | 그리퍼가 무언가를 쥐고 있는지 (3.3장) | 참·거짓 |

`state`(읽기 전용): `idle`(대기) · `busy`(작업 중) · `teleop`(리더암 따라감) · `relaxed`(힘 빠짐).

## 3. 작업 = 단계 목록

작업과 자세는 서버 쪽 설정 파일(예: `arm.json`)에 둡니다. 코드에 각도를 넣지 않습니다.
원점은 서버가 저장하지 않습니다 — HMI가 저장하고 원점 복귀 명령이 각도를 가져옵니다 ([xml-protocol.md 3장](xml-protocol.md#3-원점--hmi가-저장-사용자-2026-10-14)).

```json
{
  "unit": "deg",
  "speed": { "joint_deg_s": 60, "gripper_pct_s": 120 },
  "gripper": { "open": 70, "close": 5, "holding_min": 12 },
  "poses": {
    "wait":       { "shoulder_pan": 0,  "shoulder_lift": -35, "elbow_flex": 70, "wrist_flex": 45, "wrist_roll": 0,  "gripper": 20 },
    "above_pick": { "shoulder_pan": 18, "shoulder_lift": -5,  "elbow_flex": 35, "wrist_flex": 60, "wrist_roll": 0,  "gripper": 70 },
    "pick":       { "shoulder_pan": 18, "shoulder_lift": 8,   "elbow_flex": 22, "wrist_flex": 62, "wrist_roll": 0,  "gripper": 70 },
    "above_bin":  { "shoulder_pan": -70, "shoulder_lift": -15, "elbow_flex": 45, "wrist_flex": 50, "wrist_roll": 30, "gripper": 12 },
    "rest":       { "shoulder_pan": 0,  "shoulder_lift": -95, "elbow_flex": 95, "wrist_flex": 70, "wrist_roll": 0,  "gripper": 10 }
  },
  "tasks": {
    "sort_defect": {
      "retry": { "times": 1, "from": 0 },
      "steps": [
        { "pose": "above_pick" },
        { "pose": "pick" },
        { "gripper": "close", "expect": "holding" },
        { "pose": "above_pick" },
        { "pose": "above_bin" },
        { "gripper": "open" },
        { "pose": "wait" }
      ]
    },
    "park": { "steps": [ { "pose": "rest" } ] }
  }
}
```

위 각도는 모양을 보이려는 예시입니다. 실제 값은 3.4장의 방법으로 읽습니다. 자세의 `gripper` 값은 읽은 그대로 두는 기록이고, 그리퍼는 `gripper` 단계로만 움직입니다.

### 3.1 단계 종류

| 단계 | 적는 값 | 하는 일 | 끝나는 때 | 실패 |
|---|---|---|---|---|
| `pose` | 자세 이름, `timeout_s` (기본: 거리 ÷ 속도 + 2초) | 관절 5개(그리퍼 빼고)를 그 자세로 보간 이동 (5장). 쥔 부품을 놓치지 않게 그리퍼는 움직이지 않음 | 관절 5개가 모두 1.5° 안에 들어옴 | 시간 초과 → `ARM_MOTION_TIMEOUT` |
| `gripper` | `open` · `close` · 0~100, `expect: "holding"` | 그리퍼만 움직임 | 그리퍼가 멈춤 (부품을 쥐면 목표 전에 멈춤) | `expect`인데 빈손 → `GRIP_FAILED` |
| `policy` | 정책 이름, `timeout_s`, `until`: `holding` · `released` · `done` | 학습 정책을 돌림 (카메라·관절을 보고 동작을 냄) | `until` 조건이 맞음 (`done`은 정책이 끝났다고 알릴 때) | 시간 초과 → `until`이 `holding`이면 `GRIP_FAILED`, 아니면 `ARM_MOTION_TIMEOUT` |
| `wait` | `ms` | 그 자리에서 기다림 | 시간이 지남 | — |
| `check` | `holding` · `empty` | 그리퍼 상태만 확인 | 바로 | 다르면 `GRIP_FAILED` |

정해 둔 자세와 정책을 섞은 예입니다. 다가가기와 옮기기는 자세로 하고, 집기만 정책으로 합니다.

```json
"sort_defect": {
  "retry": { "times": 1, "from": 0 },
  "steps": [
    { "pose": "above_pick" },
    { "policy": "grasp_part", "timeout_s": 8, "until": "holding" },
    { "pose": "above_bin" },
    { "gripper": "open" },
    { "pose": "wait" }
  ]
}
```

### 3.2 다시 시도

실패하면 그리퍼를 연 뒤 `retry.from` 단계(0부터 센 번호)부터 `retry.times`번까지 다시 합니다. 다시 할 때 서버는 HMI에 `sort_retry` 이벤트를 보냅니다.
그래도 실패하면 작업 실패로 돌려줍니다.

### 3.3 쥐었는지 판단 (`holding`)

그리퍼를 닫았는데 `gripper.holding_min`(%)보다 더 닫혔으면 빈손으로 봅니다. 부품에 막혀 덜 닫혀야 쥔 것입니다.
기준은 부품 크기에 맞춰 정하고, 그리퍼 서보의 부하 값을 함께 봐도 됩니다.

### 3.4 자세 값 읽기

자세 값은 HMI 장치 점검([`tools/devices.html`](../hmi-web-mockup/tools/devices.html))의 **자세 저장**으로 만듭니다.
로봇팔을 손으로 그 자세에 두고 이름을 고른 뒤 "지금 자세 저장"을 누르면 위 `poses` 모양으로 모입니다 (LeRobot과 같은 계산).
원점은 여기서 만들지 않습니다 — 서버를 켠 채 수동 모드에서 HMI의 "원점 잡기"로 HMI(브라우저)에 저장합니다.
서보 포트는 한 프로그램만 열 수 있어 서버를 끈 상태에서 합니다.

## 4. 작업 결과

```json
{ "ok": false, "code": "GRIP_FAILED", "step": 2, "step_name": "gripper_close", "retries": 1 }
```

| code | 뜻 | 공정 제어가 할 일 |
|---|---|---|
| 없음 (`ok: true`) | 성공 | 다음 단계로 |
| `GRIP_FAILED` | 다시 해도 부품을 집지 못함 | 라인을 세우고 고장으로 알림. 원점 복귀를 해야 자동으로 다시 시작 |
| `ARM_MOTION_TIMEOUT` | 정해진 시간 안에 자세에 닿지 못함 (걸림·과부하) | 라인을 세우고 고장으로 알림. 원점 복귀를 해야 자동으로 다시 시작 |
| `ABORTED` | `stop()`·`relax()`로 끊김 | 끊은 쪽이 처리 |
| `SERVO_OVERHEAT` · `POWER_ABNORMAL` | 서보 이상 | API.md 3.1장의 고장 규칙대로 |

## 5. 움직임 규칙

- 자세 이동은 관절마다 **보간**합니다. 목표를 한 번에 보내지 않고 30~50Hz로 조금씩 옮겨 보냅니다. LeRobot 기본 설정에서는 먼 목표를 한 번에 보내면 팔이 빠르게 튀듯 움직입니다. 최대 속도는 `speed.joint_deg_s` (초안 60°/s).
- 관절 한계: 캘리브레이션 범위 안의 값만 보냅니다. 설정 파일을 읽을 때 자세 값이 범위 밖이면 `connect()`에서 거절합니다 (고쳐야 시작).
- 학습 정책: LeRobot 로봇 설정의 `max_relative_target`을 정하기를 권합니다. 매 순간 목표 위치가 지금 위치에서 그 값보다 멀면 잘라 주므로, 정책이 엉뚱한 값을 내도 급하게 움직이지 않습니다. 기본값은 없음(자르지 않음)입니다.
- 정책이 보는 카메라가 판정 카메라와 같으면 서버 안에서 한 번만 열고 장면을 나눠 씁니다 (카메라는 한 프로그램만 엶).
- 그리퍼는 쥔 채 오래 버티면 서보가 과부하·과열됩니다. 쥐는 시간을 짧게 하고, 닫힘 목표를 부품 폭보다 조금만 작게 잡습니다.
- 작업 중 목표 각도를 HMI에 `joints`(source `target`)로 보내면 대시보드에서 목표와 실제를 비교할 수 있습니다 (선택).

## 6. 멈출 때

| 상황 | 로봇팔 | 이유 |
|---|---|---|
| 정지 (일반) | 하던 작업을 끝내고 대기 자세(`wait`)에서 멈춤. 힘 유지 | 부품을 쥔 채 멈추지 않게 |
| 고장 (집기 실패·자세 시간 초과 등) | 지금 단계에서 멈춤(`stop()`). 힘 유지. 원점 복귀를 해야 자동으로 다시 시작 | 사람이 원인을 보고 부품을 치운 뒤 시작하게 |
| 화면 긴급정지 | 바로 힘 빼기(`relax()`). 팔이 아래로 처짐 | 끼였을 때 풀리고, 하드웨어 비상정지(DC 전원 차단)와 결과가 같음. 비상정지는 정지 범주 0 또는 1로 하라는 것이 IEC 60204-1의 규칙 |
| 긴급정지 해제 | 지금 처진 자세를 목표로 힘을 다시 줌 (튀지 않게). 원점 복귀를 해야 자동으로 다시 시작 (수동 시작은 막지 않음) | 자세를 모르는 채로 자동 작업을 시작하지 않게 |
| 서버가 멈춤·끊김 | 서보가 마지막 목표 자세를 그대로 버팀 | 서보가 스스로 버팀. 컨베이어는 감시 타이머로 멈춤 |
| 프로그램 종료 (F-03) | 접은 자세(`park` 작업)로 옮긴 뒤 힘 빼기 | LeRobot은 연결을 끊을 때 힘을 뺌 (`disable_torque_on_disconnect` 기본 켜짐). 높은 곳에서 힘이 빠져 떨어지지 않게 |

## 7. HMI로 가는 것 (API.md와 이어짐)

| 로봇팔 제어에서 | HMI로 |
|---|---|
| `telemetry()`를 1~2Hz로 | `telemetry` 메시지 |
| 움직일 때 지금 각도 | `joints` (source `arm`) |
| 작업 중인 단계 이름 | 상태 `cycle.step` (예 `pick`, `grasp_part`) |
| 다시 시도 | 이벤트 `sort_retry` |
| 작업 실패 | 상태 `fault` (`GRIP_FAILED` · `ARM_MOTION_TIMEOUT`, `clear: "home"`) + 이벤트 `line_halted` |
| 긴급정지·로봇팔 고장 뒤 | 상태 `home_required: true`. 원점 복귀를 마치면 `false` (원점 잡기는 서버에 알리지 않아 풀지 않음) |

## 8. 수동 모드 (리더암)

- `teleop(True)`: 리더암 6축을 읽어 30Hz 이상으로 로봇팔에 보냅니다 (LeRobot 원격 조작과 같은 방식). `max_relative_target`도 그대로 씁니다.
- 원점 잡기: 사람이 리더암으로 로봇팔을 원하는 자세에 둔 뒤 HMI의 "원점 잡기"를 누르면 HMI가 서버가 보낸 지금 각도(로봇팔 각도, 없으면 리더암 각도)를 원점으로 저장합니다. 리더암을 따라가는 중(가동 중)에도 되고, 긴급정지 중(힘이 빠짐)에는 HMI가 막습니다. 서버가 할 일은 각도를 계속 보내는 것뿐입니다.
- 수동 모드에서 컨베이어를 어떻게 돌릴지는 [공정 순서 5장](line-sequence.md#5-수동-모드-초안)의 정할 것입니다.
- 정책을 학습할 시연 녹화(LeRobot `lerobot-record`)는 지금은 서버를 끈 상태에서 따로 합니다 (같은 포트를 씀). 서버 안에 녹화 기능을 넣을지는 정할 것입니다.

## 9. 정할 것

- [ ] 자동 모드의 작업을 자세만 / 정책만 / 섞어서 할지. 위 설정 모양은 셋 다 됩니다
- [ ] 화면 긴급정지 때 힘 빼기(초안)와 그 자리에서 버티기 중 무엇으로 할지
- [ ] 자세 이동 최대 속도(초안 60°/s), 단계 시간 제한, 다시 시도 횟수(초안 1번)
- [ ] 쥐었는지 판단 기준(`holding_min`)과 부품 크기
- [ ] 긴급정지·로봇팔 고장 뒤 자동 시작 전에 원점 복귀를 꼭 거치게 할지 (초안: 그렇게 함 → `409 HOME_REQUIRED`)
- [ ] 원점을 자동 작업에서 어떻게 쓸지 (예: 대기 자세 `wait` 대신 원점에서 작업을 시작·끝낼지), 원점을 저장할 파일
- [ ] 로봇팔 제어를 서버와 같은 프로그램에 둘지, 시연 녹화를 서버에 넣을지
