# 서버 ↔ 컨베이어(아두이노) 시리얼 규약 (v1 초안)

서버가 USB로 아두이노 컨베이어를 움직이고 상태를 받는 약속입니다. 아두이노 스케치를 만드는 사람과 서버를 만드는 사람이 이 문서 하나로 맞춥니다.
컨베이어의 모터·센서 구성은 아직 정해지지 않았습니다. 그래서 아두이노가 **자기가 가진 기능을 먼저 알려 주고**, 서버가 그 기능에 맞춰 쓰는 방식으로 잡았습니다.

- 만든 스케치가 이 규약대로 답하는지는 [장치 점검](../hmi-web-mockup/tools/devices.html)의 "컨베이어 점검"으로 확인합니다.
- 하드웨어 없이 시험하는 가짜 컨베이어와 서버 쪽 견본 코드는 [`hmi-web-mockup/js/conveyor.js`](../hmi-web-mockup/js/conveyor.js)에 있습니다. HMI의 가짜 서버도 이 코드로 가짜 컨베이어를 움직입니다.
- 이 규약을 언제 어떻게 쓰는지(부품마다 멈추기 등)는 [공정 순서](line-sequence.md)에 있습니다.

## 1. 연결과 메시지 모양

| 항목 | 값 |
|---|---|
| 연결 | USB 시리얼 (아두이노 보드의 USB) |
| 속도 | 115200bps, 8N1 |
| 글자 | ASCII, 한 줄에 메시지 하나. 줄 끝은 `\n` (`\r\n`으로 와도 받는 쪽은 `\r`을 버림) |
| 줄 길이 | 64글자 이하 |
| 대소문자 | 명령은 대문자로 보냄. 아두이노는 소문자로 와도 받기를 권장 (시리얼 모니터에서 손으로 칠 때) |

| 방향 | 모양 | 예 |
|---|---|---|
| 서버 → 아두이노 (명령) | `명령 [값]` | `RUN`, `SPEED 40` |
| 아두이노 → 서버 (응답) | `OK [이름=값 …]` 또는 `ERR 코드` | `OK speed=40`, `ERR HALTED` |
| 아두이노 → 서버 (알림) | `!이름 [값] [이름=값 …]` | `!PART 1`, `!STATE halted reason=watchdog` |

- 명령 하나에 응답은 꼭 한 줄입니다. 모르는 명령에도 `ERR UNKNOWN`으로 답합니다 (서버가 하염없이 기다리지 않게).
- 응답은 명령을 받고 50ms 안에 보냅니다. 오래 걸리는 동작(감속 정지 등)은 받았다는 응답만 바로 하고, 끝난 것은 `!STATE` 알림으로 알립니다.
- 서버는 응답을 받은 뒤에 다음 명령을 보냅니다 (한 번에 하나). 응답과 알림은 첫 글자(`!`)로 구분합니다.
- 그 밖의 줄(스케치의 디버그 출력 등)은 서버가 무시합니다. 단 `OK`·`ERR`·`!`로 시작하는 디버그 출력은 쓰지 마세요.

## 2. 명령

| 명령 | 성공 응답 | 실패 응답 | 하는 일 |
|---|---|---|---|
| `INFO` | `OK proto=1 name=… fw=… speed=… sensor=… autostop=… button=… watchdog=…` | — | 규약 판과 가진 기능 (3장) |
| `STATUS` | `OK state=… reason=… speed=… part=… autostop=…` | — | 지금 상태 (4장) |
| `RUN` | `OK` | `ERR HALTED` | 설정 속도로 가동 |
| `STOP` | `OK` | — | 정지 (감속해도 됨). 잠그지 않음. 이미 잠겨(`halted`) 있으면 잠긴 그대로 |
| `HALT` | `OK` | — | 바로 멈추고 잠금. `RESET` 전까지 `RUN`을 거절 |
| `RESET` | `OK` | `ERR FAULT` | 잠금 해제. 멈춘 상태 그대로 (저절로 움직이지 않음) |
| `SPEED n` | `OK speed=n` | `ERR BAD_ARG` · `ERR UNSUPPORTED` | 속도 n% (0~100). 가동 중이면 바로 바뀜 |
| `AUTOSTOP 0` · `AUTOSTOP 1` | `OK autostop=1` | `ERR BAD_ARG` · `ERR UNSUPPORTED` | 1이면 센서에 부품이 오는 순간 아두이노가 스스로 멈춤 (5장) |
| `PING` | `OK` | — | 살아 있음. 감시 타이머를 다시 잼 (6장) |

| 오류 코드 | 뜻 |
|---|---|
| `UNKNOWN` | 모르는 명령 |
| `BAD_ARG` | 값이 없거나 범위 밖 |
| `HALTED` | 잠겨 있어 가동할 수 없음 (`RESET` 필요) |
| `UNSUPPORTED` | 이 컨베이어에 없는 기능 (속도 조절이 안 되는 모터의 `SPEED` 등) |
| `FAULT` | 이상이 남아 있어 잠금을 풀 수 없음 |
| `TOO_LONG` | 줄이 64글자를 넘음 |

## 3. 기능 알림 (`INFO`)

| 이름 | 값 | 뜻 |
|---|---|---|
| `proto` | `1` | 규약 판. 서버는 1이 아니면 쓰지 않고 알림 |
| `name` | 빈칸 없는 글자 | 장치 이름. 예 `conveyor` |
| `fw` | 빈칸 없는 글자 | 스케치 판. 예 `0.1.0` |
| `speed` | `0` · `1` | 속도 조절 가능 (`SPEED`) |
| `sensor` | `0` · `1` | 부품 도착 센서 있음 (`!PART`) |
| `autostop` | `0` · `1` | 센서로 스스로 멈추기 가능 (`AUTOSTOP`) |
| `button` | `0` · `1` | 아두이노에 정지 단추가 달림 |
| `watchdog` | ms | 감시 시간. 가동 중 이 시간 동안 아무 줄도 못 받으면 스스로 멈춤 |

서버는 모르는 이름을 무시합니다. 나중에 기능을 더하면 이름을 더하고 `proto`는 그대로 둡니다.

## 4. 상태 (`STATUS`, `!STATE`)

| 이름 | 값 | 뜻 |
|---|---|---|
| `state` | `stopped` · `running` · `halted` | 멈춤 · 가동 · 잠긴 정지 |
| `reason` | `boot` · `command` · `part` · `watchdog` · `button` · `fault` | 마지막으로 상태가 바뀐 이유 |
| `speed` | 0~100 또는 `-` | 설정 속도(%). 속도 조절이 없으면 `-` |
| `part` | `0` · `1` · `-` | 센서에 부품이 있음. 센서가 없으면 `-` |
| `autostop` | `0` · `1` | 스스로 멈추기가 켜져 있는지 |
| `code` | 빈칸 없는 글자 | `reason=fault`일 때만. 스케치가 찾은 이상 이름 (예 `MOTOR_DRIVER`) |

상태가 바뀌면 아두이노가 바로 알립니다. 예: `!STATE running reason=command`, `!STATE stopped reason=part`, `!STATE halted reason=watchdog`.

| reason | 언제 | 바뀌는 상태 |
|---|---|---|
| `boot` | 켜짐·리셋 | `stopped` |
| `command` | `RUN`·`STOP`·`HALT`·`RESET` | 명령대로 |
| `part` | 스스로 멈추기가 켜져 있고 센서에 부품이 옴 | `stopped` |
| `watchdog` | 가동 중 감시 시간 동안 줄을 못 받음 | `halted` |
| `button` | 아두이노의 정지 단추 | `halted` |
| `fault` | 모터 드라이버 이상 등 스케치가 찾은 이상 | `halted` |

## 5. 알림

| 알림 | 언제 |
|---|---|
| `!READY proto=1` | 켜지거나 리셋된 직후 한 번. 이때 상태는 `stopped` |
| `!STATE <상태> reason=<이유> [code=…]` | 상태가 바뀔 때 |
| `!PART 1` · `!PART 0` | 센서에 부품이 들어옴 · 빠짐 (센서가 있을 때). 떨림은 스케치가 걸러서(예: 20ms) 한 번씩만 |

스스로 멈추기(`AUTOSTOP 1`)는 센서 값이 0에서 1로 바뀌는 순간에만 멈춥니다. 서버가 다시 `RUN`하면 그 부품이 센서를 다 지나갈 때까지는 다시 멈추지 않습니다.
알림 순서는 `!PART 1` 다음 `!STATE stopped reason=part`입니다. 서버가 멈추라고 보내는 것보다 빨라, 부품이 늘 같은 자리에 섭니다.

## 6. 감시 타이머 — 서버가 멈추면 벨트도 멈춘다

- 아두이노는 줄을 하나 받을 때마다(명령이 무엇이든) 감시 타이머를 처음부터 잽니다.
- **가동 중**에 `watchdog`(기본 1000ms) 동안 아무 줄도 못 받으면 모터를 멈추고 `halted`(잠김)로 바꾼 뒤 `!STATE halted reason=watchdog`을 보냅니다.
- 서버는 연결되어 있는 동안 250ms마다 `PING`을 보냅니다. 감시 시간이 1000ms보다 짧은 컨베이어면 감시 시간의 1/4마다 보냅니다. 다른 명령을 보내면 그것도 감시 타이머를 다시 잽니다.
- 잠김(`halted`)은 `RESET`으로만 풀립니다. 서버가 다시 살아나도 벨트가 저절로 움직이지 않게 하려는 것입니다.

서버 쪽 판단
- 응답이 200ms 안에 안 오면 놓친 것으로 셉니다. 3번 이어서 놓치면 컨베이어 연결이 끊긴 것으로 봅니다 (HMI 상태 `devices.conveyor = "disconnected"`).
- 응답에는 번호가 없어서, 시간을 넘겨 늦게 온 응답이 다음 명령의 응답으로 읽힐 수 있습니다. 그래서 `RUN`·`HALT`처럼 중요한 명령은 응답만 믿지 않고 `!STATE` 알림(또는 `STATUS`)으로 실제로 바뀌었는지 확인합니다.
- 서버가 보내지 않았는데 `!READY`가 오면 아두이노가 리셋된 것입니다 (전원 흔들림 등). 가동 중이었으면 고장으로 라인을 세웁니다 ([공정 순서 3장](line-sequence.md#3-시간-제한과-고장)).

## 7. 연결 순서 (서버)

1. 포트를 엽니다. **우노·나노·메가는 포트를 열면 리셋됩니다.** `!READY`를 최대 3초 기다립니다 (리셋되지 않는 보드면 기다리다 넘어감).
2. `INFO` — `proto=1`인지, 어떤 기능이 있는지 봅니다.
3. `STOP` — 멈춘 상태에서 시작합니다. `halted`면 그대로 둡니다 (라인을 시작할 때 `RESET`).
4. 기능이 있으면 `SPEED <설정값>`, 부품마다 멈추는 운전이면 `AUTOSTOP 1`.
5. `PING`을 250ms마다 보내기 시작합니다.

## 8. 주고받기 예

라인 시작 → 부품 도착 → 판정 뒤 다시 가동 (센서와 스스로 멈추기가 있는 컨베이어)

```text
→ RESET              ← OK
→ RUN                ← OK
                     ← !STATE running reason=command
→ PING               ← OK
                     ← !PART 1
                     ← !STATE stopped reason=part        (서버가 촬영·판정)
→ RUN                ← OK
                     ← !STATE running reason=command
                     ← !PART 0                           (부품이 센서를 지나감)
```

긴급정지와 해제

```text
→ HALT               ← OK
                     ← !STATE halted reason=command
→ RUN                ← ERR HALTED
→ RESET              ← OK
                     ← !STATE stopped reason=command
```

서버가 멈춤 (PING이 끊김)

```text
                     ← !STATE halted reason=watchdog     (마지막 줄을 받고 1초 뒤)
```

## 9. 아두이노 스케치를 만들 때

- `loop()`를 막는 `delay()`를 쓰지 마세요. 줄 받기·감시 타이머·센서 읽기가 늘 돌아야 합니다 (`millis()`로 시간을 잼).
- 켜질 때 모터는 꺼진 채로 시작합니다. `!READY` 전에 움직이지 않습니다.
- 정지 단추를 달면 단추로 멈춘 것도 `halted`(잠김)입니다. 풀기는 서버의 `RESET`으로만 합니다.
- 다 만들면 장치 점검의 **컨베이어 점검**으로 확인하세요. 응답 모양, 잠금, 감시 타이머, 기능별 명령을 차례로 시험합니다 (시험 중 벨트가 움직입니다).
- 이 규약은 **안전 장치가 아닙니다.** 비상 정지는 컨베이어·로봇팔 DC 전원을 함께 끊는 하드웨어 스위치로 하세요 ([API 8장](API.md#8-안전-메모)).

## 10. 정할 것

- [ ] 모터·드라이버 종류(속도 조절 여부), 부품 센서 유무와 위치, 정지 단추 유무. 정해지면 `INFO`의 값만 맞추면 됩니다
- [ ] 감시 시간 1000ms, `PING` 250ms가 맞는지
- [ ] 아두이노 보드 종류(포트를 열 때 리셋되는지), 속도 기본값
- [ ] 벨트를 거꾸로 돌릴 일이 있는지. 있으면 `DIR` 명령을 더합니다
