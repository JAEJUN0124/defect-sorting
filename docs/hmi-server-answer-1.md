### 0.1 HMI 화면은 Cloudflare에서 띄웁니다 (서버 쪽 할 일 없음)

HMI 화면을 장비망 밖에서도 열 수 있게, 화면과 연결을 Cloudflare로 옮겼습니다. 서버 코드와 `/ws/hmi` 규약은 바꾸지 않습니다.

- 여는 주소: `https://hmi.hypefree.net/` (서버 점검은 `/tools/server-check.html`). 허락한 이메일로 일회용 코드를 받아 로그인합니다 (Cloudflare Access). 밖에서 열어 보시려면 쓰실 이메일을 알려 주세요. 허용 목록에 넣겠습니다.
- 연결: 브라우저 → Cloudflare(화면 파일, 웹소켓은 WSS로 받음) → Cloudflare Tunnel → 장비망 안 PC의 `cloudflared` → 서버 `http://192.168.219.101:8000/ws/hmi`. 서버가 받는 것은 지금처럼 평범한 웹소켓(`ws://`)입니다.
- 밖에서 들어오는 연결은 모두 Cloudflare Access(허락한 사람 · 서비스 토큰)와 TLS를 거칩니다. 서버 README와 영상 안내 8장의 "외부 연결은 VPN 또는 인증과 TLS를 갖춘 프록시 등으로 접근을 제한" 조건을 이것으로 맞췄습니다. 서버의 다른 경로(`/`, 영상 확인 화면 `/video` 등)는 밖에 열지 않고 `/ws/hmi`와 영상 세 경로(`/video/status` · `/video/1.mjpg` · `/video/2.mjpg`)만 넘깁니다.
- 영상도 HMI 화면과 같은 주소로 넘겨 받으므로, 서버에 CORS 설정을 더하지 않으셔도 됩니다 (영상 안내 8장).
- 밖에서 연 HMI의 요청은 모두 `cloudflared`를 돌리는 HMI 담당 PC(지금 `10.108.108.216`)에서 오는 것으로 서버에 보입니다. 접속 기록을 보실 때 참고해 주세요.
- 부탁드리는 것은 두 가지입니다.
  1. 서버를 지금처럼 `http://192.168.219.101:8000`에 켜 두세요. 주소나 포트를 바꾸시면 알려 주세요 (터널 설정을 고쳐야 합니다).
  2. 영상 경로가 바뀌거나 HTTP로 보내는 것이 더 생기면 그 경로를 알려 주세요. Cloudflare 쪽에서 그 경로도 넘기게 하겠습니다.
- 장비망 안에서 지금처럼 `ws://192.168.219.101:8000/ws/hmi`에 바로 붙는 것도 그대로 됩니다 (인터넷이 끊겼을 때의 예비).
- 전에 말씀드리려던 "메인 서버에서 화면 띄우기"(`wwwroot/`와 `app.UseDefaultFiles(); app.UseStaticFiles();`)는 하지 않으셔도 됩니다. 장비망 안에서 인터넷 없이도 메인 서버로 화면을 띄우고 싶으시면 그때 묶음을 보내 드리겠습니다.
- 실제 서버로 확인했습니다 (2026-10-17): 장비망 밖에서 `https://hmi.hypefree.net/`으로 붙어 상태 받기와 영상까지 됩니다 (6장, 8.3).

### 0.2 보내 주시거나 알려 주실 것 (코드 작업 아님)

1. **고치신 서버 README 새 판.** 저희가 가진 사본은 고치기 전 판입니다.
2. **2차(공유 `Line` 상태와 시뮬레이션)를 시작하실 때와 마치셨을 때 알려 주세요.** HMI를 붙여 같이 확인하겠습니다.

### 0.3 같이 정할 것 — HMI 쪽 제안 (좋으면 제안대로, 다르면 알려 주세요)

4. **그리퍼(6번 모터) 단위.** 제안: 6번은 LeRobot 값 그대로 0~100을 `unit="percent"`로 보내고(상태의 `RobotArm/Motors`), `Home`의 `Motors`에서도 6번은 `percent`를 받기. 1~5번은 지금처럼 `deg`.
   HMI는 `deg`·`percent`를 둘 다 읽고, 받은 단위 그대로 저장해서 `Home`에 실어 보냅니다. 지금 서버 검사는 `deg`만 받아 6번이 `percent`면 `InvalidAngles`입니다. `deg`로 두시려면 0~100을 도로 바꾸는 방법을 알려 주세요.
5. **같은 id로 다시 온 명령.** 제안: 같은 연결에서 이미 받은 id의 `Command`가 다시 오면 다시 실행하지 않고 처음 보낸 `Reply`를 그대로 다시 보내기 (최근 id 수십 개를 기억).
   지금은 같은 id 5개에 5개 모두 받음 확인이 옵니다(6장). 장비를 연결하는 3차 "실행 명령 중복 방지"에서 정해 주세요. HMI는 누를 때마다 새 id를 쓰고 자동으로 다시 보내지 않습니다.

### 0.4 2차에서 하시기로 한 것 — HMI가 이미 읽는 모양 (회신 6장 2차)

이 모양대로 더하시면 HMI는 고치지 않아도 됩니다. 이름이나 모양을 바꾸시면 알려 주세요. HMI가 맞추겠습니다.

6. **상태에 라인 상태 `Line`.**

   ```xml
   <Status source="simulation">
     <Line state="Running" mode="Auto" emergencyStop="false" homeRequired="false" startedAt="2026-10-17T01:00:00Z" />
     <Equipment>…지금과 같음…</Equipment>
     <Inspection valid="true">…지금과 같음…</Inspection>
   </Status>
   ```

   - `state`: `Stopped` · `Starting` · `Running` · `Stopping` · `Homing` (긴급정지 중에는 `Stopped`)
   - `mode`: `Auto` · `Manual` (요청한 목표가 아니라 실제 모드) / `emergencyStop` · `homeRequired`: `true` · `false` / `startedAt`: 이번 가동을 시작한 때 (선택)
   - 장비 연결 전(`source="unavailable"`)에는 `Line`을 빼 주세요. HMI는 "상태 미수신"으로 보이고 키를 막지 않습니다. 시뮬레이션에서만 가상 `Line`을 보내 주세요.
7. **운전 규칙 (서버도 같은 규칙으로 거절):**
   - 운전 모드 전환은 정지 상태에서만 합니다.
   - 긴급정지를 해제해도 라인은 정지 상태로 남고 저절로 다시 가동하지 않습니다.
   - 원점 복귀는 자동 모드·정지 상태에서만 합니다.
   - 긴급정지 뒤에는 `homeRequired="true"`, 원점 복귀를 마치면 `false`. 자동 모드에서 `homeRequired="true"`면 시작을 거절합니다.
   - 수동 모드가 면제받는 것은 원점 복귀 요구뿐입니다. 긴급정지·고장·장치 연결 검사는 수동 모드에서도 그대로입니다.
8. **상태 때문에 못 하는 명령의 거절** (`Reply result="Rejected" executed="false"`, 형식 오류 코드는 지금 그대로):

   | `code` | 뜻 | 쓰는 명령 |
   |---|---|---|
   | `EstopActive` | 긴급정지 중 | 시작 · 운전 모드 · 원점 복귀 |
   | `EstopNotActive` | 긴급정지 중이 아님 | 긴급정지 해제 |
   | `InvalidState` | 지금 상태에서 못 함 (가동 중에 시작, 멈춰 있는데 정지) | 시작 · 정지 |
   | `NotStopped` | 정지 상태가 아님 | 운전 모드 · 원점 복귀 |
   | `NotAuto` | 자동 모드가 아님 | 원점 복귀 |
   | `HomeRequired` | 원점 복귀를 먼저 해야 함 (자동 모드) | 시작 |
   | `HomeNotSet` | 원점 각도가 없음 | 원점 복귀 |
   | `DevicesNotReady` | 장치가 연결 안 됨 — `<Param name="missing">Conveyor</Param>`를 장치마다 (`Conveyor` · `RobotArm` · `LeaderArm` · `Camera:top`) | 시작 · 원점 복귀 |
   | `FaultActive` | 고장이 남아 있음 — `<Param name="fault">ServoOverheat</Param>` | 시작 |

9. **받아서 장비 제어 쪽에 넘겼을 때:** `Reply result="Received" code="Accepted" executed="true"`. 동작 완료가 아니라 "실행 요청을 받아들임"입니다. 완료는 아래 이벤트와 상태로 알려 주세요.
10. **이벤트.**

    ```xml
    <Message version="1.0" type="Event" timestamp="2026-10-17T01:00:05Z">
      <Event code="LineStopped" level="Info" seq="12"><Param name="requestId">hmi-k3f9-stop-4</Param></Event>
    </Message>
    ```

    - `code`: `LineStarted` · `LineStopped` · `EstopPressed`(`Alarm`) · `EstopReleased` · `ModeChanged`(+`<Param name="mode">`) · `HomeStarted` · `HomeCompleted` · `DeviceDisconnected`(`Warning`, +`<Param name="device">`) · `DeviceReconnected`(+`device`)
    - `level`: `Info` · `Warning` · `Alarm`. `seq`가 서버를 다시 켜면 1부터인 것은 괜찮습니다.
    - 완료 이벤트(`HomeCompleted` · `LineStopped`)의 `requestId`는 있으면 좋고 없어도 됩니다. HMI는 이벤트로 화면을 바꾸지 않고 로그에 남깁니다.
11. **상태가 바뀌면 바로, 모든 HMI에.** 라인 상태·긴급정지·운전 모드·장치 연결이 바뀌면 주기 전송을 기다리지 말고 접속한 모든 HMI에 상태를 바로 보내 주세요. `Reply`는 지금처럼 요청한 HMI에만.
12. **확인 기준:** HMI 화면을 여러 개(여러 창·여러 PC) 동시에 붙였을 때, 한 화면의 시작·긴급정지·원점 복귀가 나머지 화면에도 바로 보이고, `Reply`는 요청한 화면에만 가고, 다시 접속하면 최신 상태로 돌아오면 됩니다.

고장(`Fault`), 판정 하나하나(`Inspection` 메시지), 팔로워 각도(`Motors role="follower"`), 리더암 연결은 장비를 연결하는 3차에 보내 주시면 됩니다. 모양은 보내 드린 요청서(hmi-server-requests) 3~4장 그대로이고, HMI는 이미 읽습니다. 카메라 연결은 영상 안내대로 `/video/status`로 보므로 XML에 넣지 않으셔도 됩니다.

### 0.5 새로 부탁드리는 것 — 로봇팔이 옮길 부품 선택값 받기 (2026-10-17)

HMI에서 작업자가 로봇팔이 옮길 부품을 **양품·불량품 중에서 고르면, HMI는 고른 값을 서버에 보냅니다.** HMI는 부품을 판정하지 않고 고른 값만 보냅니다. 이 값을 어떻게 쓸지(판정, 로봇팔 동작)는 서버·장비 쪽에서 정하시면 됩니다.

13. **명령 `SetSortTarget`을 받아 주세요** (`target="Good"` · `"Defect"`). 지금은 다른 명령처럼 받음 확인(`ReceiptOnly`)만이어도 됩니다. 모양은 7장입니다.
14. **(선택) 서버가 가진 지금 값을 상태에 넣어 주시면**(`Line/@sortTarget`, 7.3) 여러 HMI가 같은 값을 보여 줍니다. 없어도 HMI는 동작합니다.

### 0.6 하지 않으셔도 되는 것

- `Stop` 별칭: HMI의 정지 키가 `ProgramStop`을 보냅니다.
- `ShutdownCompleted`: 프로그램 종료는 HMI만 닫고 서버에 보내지 않습니다.
- 상태 전송 간격(`PushIntervalMs`) 고정: HMI는 60초 간격에서도 동작합니다 (60초마다 `Ping`, 상태가 60초 넘게 없으면 `GetStatus`). 간격은 편하신 대로 바꾸셔도 됩니다.
- `Reply`·`Event`의 시뮬레이션 표시: `Status/@source`로 충분합니다.
- 카메라 명령 · XML의 `Camera` 요소 · CORS 설정: 영상은 보내 주신 안내대로 HTTP(MJPEG와 `/video/status`)로만 받고, HMI 화면과 같은 주소로 넘겨 받습니다 (8장).
- 공정 단계(`Cycle`, 요청서 4.2): 이 값을 보이던 대시보드를 없애(2026-10-17) 지금은 보내지 않으셔도 됩니다.
- 외부 접속(공인 주소 · 포트포워딩 · HTTPS/WSS)과 HMI 화면 파일 내주기: HMI가 Cloudflare로 합니다 (0.1).
- `SetSortTarget`을 지금 장비에 연결하는 것: 장비 연결 전에는 받음 확인만으로 충분합니다.

### 0.7 HMI 쪽에서 정해서 알려 드릴 것 (그동안 기다려 주세요)

- 수동 모드에서 시작할 때 움직일 장치, 자동 작업이 원점을 쓰는지 (장비 담당과 정함, 1장 3번)
- 통신이 끊겼을 때의 "DC 전원 케이블을 뽑으세요" 안내 (하드웨어 담당 검토, 4장). 하드웨어 비상정지 버튼을 달지도 아직 정하지 않았습니다.
- 모터 각도 범위·영점·방향 (로봇팔 배선·캘리브레이션 뒤, 1장 4번 — 이제 시작합니다)

## 1. 회신 5장 질문에 대한 답

| # | 질문 | HMI 답 |
|---|---|---|
| 1 | `ProgramStop`을 장비 정지로 두고 `Stop`을 별칭으로 더하는 안 | `ProgramStop` = 장비(컨베이어·로봇팔) 정지 요청으로 좋습니다. HMI의 정지 키(가동 중에 시작 키가 "정지"로 바뀜)가 이제 `ProgramStop`을 보내므로 `Stop` 별칭은 HMI에는 필요 없습니다. **"프로그램 종료" 버튼은 HMI 화면만 닫고 서버에는 아무것도 보내지 않게** 바꿨습니다. 그래서 장비 정지 완료와 종료 화면을 잇는 규칙도 필요 없습니다. |
| 2 | 5초 뒤 종료 화면 전환, 거절 Reply의 `mode` 매칭 | 5초 뒤 종료 화면은 없앴습니다 (프로그램 종료가 서버를 거치지 않음). 거절 Reply는 HMI가 원래 **id로 찾고, 답에 있는 값만** 비교하고 있었습니다 — 요청서의 "모두 맞을 때만" 문장이 오해를 드렸습니다. `mode`·`command`가 없는 거절도 그 요청의 답으로 쓰고, `command`가 없으면 보낸 명령 이름으로 문구를 고릅니다. id 없는 `Error`는 어느 요청도 끝내지 않습니다. |
| 3 | 수동 모드에서 시작할 때 가동할 장치, 자동 작업의 원점 사용 | 아직 정하지 못했습니다. 장비 담당과 정한 뒤 알려 드리겠습니다. 참고로 HMI가 요청한 규칙에서 수동 모드가 면제받는 것은 원점 복귀 요구(`homeRequired`)뿐이었습니다 — 긴급정지·고장·장치 연결 검사는 수동 모드에서도 면제하지 않습니다. |
| 4 | 1~6번 모터 대응, 그리퍼 단위, 각도 범위·영점·방향, 팔로워 현재각 | 모터 번호는 LeRobot SO-101 순서입니다: 1 `shoulder_pan`(어깨 회전) · 2 `shoulder_lift`(어깨 들기) · 3 `elbow_flex`(팔꿈치) · 4 `wrist_flex`(손목 굽힘) · 5 `wrist_roll`(손목 회전) · 6 `gripper`(그리퍼). LeRobot에서 1~5번은 도(캘리브레이션 때 기록한 범위의 가운데가 0°)이고, **그리퍼는 각도가 아니라 0~100**(그 범위의 비율)입니다. 6번을 `deg`로 둘지 `percent`로 바꿀지 정해야 합니다 (제안은 0장 4번) — HMI는 `percent`도 읽고 보낼 수 있습니다 (지금 `Home` 검사는 `deg`만 받음). 범위·영점·방향은 캘리브레이션을 해야 정해집니다. 팔로워 현재각은 LeRobot에서 읽을 수 있으니, `Motors role="follower"`로 보내 주시면 HMI는 원점을 잡을 때 그것을 먼저 씁니다. 로봇팔 배선·캘리브레이션을 마치면 실제 값을 확인해 알려 드리겠습니다. |
| 5 | HMI 파일과 `tools/server-check.html` 전달 | 파일을 보내 드리는 대신 `https://hmi.hypefree.net/`에서 여시면 됩니다 (0.1). 서버 점검은 `https://hmi.hypefree.net/tools/server-check.html`이고 형식을 XML로 두고 보시면 됩니다. 서버 PC에서 파일로 보고 싶으시면 묶음을 따로 보내 드립니다 (그 안의 `wwwroot/tools/server-check.html`은 더블클릭해도 열리고 `ws://localhost:5080/ws/hmi`에 붙음). |
| 6 | HMI를 HTTPS로 제공하는지 | 정했습니다. 밖에서는 Cloudflare가 HTTPS(`https://hmi.hypefree.net/`)로 내주고, 웹소켓은 Cloudflare가 WSS로 받아 터널로 서버의 `ws://`에 넘깁니다. 서버는 WSS를 하지 않으셔도 됩니다 (0.1). 장비망 안에서 HTTP로 띄워 `ws://192.168.219.101:8000/ws/hmi`에 바로 붙는 지금 방식도 그대로 됩니다 (6장). |

## 2. 회신에서 물어보신 그 밖의 것

| 회신 | HMI 답 |
|---|---|
| 시뮬레이션 표시를 Reply·Event에도 할지 (3장) | HMI는 `Status/@source`로 봅니다 (`simulation`이면 "화면 값은 서버의 시험용 가상 데이터입니다"). Reply·Event에 따로 표시하지 않아도 됩니다. |
| 완료 이벤트의 `<Param name="requestId">` (3장) | HMI는 이벤트로 화면을 바꾸지 않고 로그에만 남깁니다. 그래서 한 화면의 요청이 끝났다고 다른 화면이 닫히는 일은 없습니다. `requestId`는 있어도 되고 없어도 됩니다 (HMI는 모르는 `Param`을 무시함). |
| `seq`가 서버 재시작 때 처음부터 (3장) | HMI가 서버를 다시 켠 뒤의 이벤트를 이미 본 것으로 버릴 수 있어 고쳤습니다. 다시 붙으면 지난 순번을 잊습니다. |
| 장비 연결 전에는 `Line`을 뺌 (3장) | 좋습니다. HMI는 `Line`이 없으면 "상태 미수신"으로 보이고 키를 막지 않습니다. |
| `executed="true"`는 실행 요청 수락이지 완료가 아님 (3장) | 동의합니다. HMI는 완료를 이벤트(`HomeCompleted` · `LineStopped`)와 상태로 봅니다. |
| 원점 저장·복귀를 어느 화면에서 허용할지 (3장) | 대시보드 두 개를 없애고 HMI 화면은 조작 화면 하나만 남겼습니다 (2026-10-17). 원점 잡기·원점 복귀는 그 화면에서 합니다. 같은 PC의 같은 브라우저에서는 창을 여러 개 열어도 원점 하나를 함께 씁니다. 다른 PC·브라우저는 원점이 따로라서 여러 HMI의 원점이 다를 수 있다는 한계는 알고 있습니다. 여러 PC에서 HMI를 쓰게 되면 다시 이야기하고 싶습니다. |
| 원점이 없는 `Home`을 `HomeNotSet`으로 거절하는 시점 (3장) | 언제 필수로 바꾸셔도 됩니다. HMI는 저장된 원점이 없으면 원점 복귀 키가 잠기고 `Home`을 보내지 않습니다. |
| 리더암 각도와 팔로워 각도가 다를 수 있음 (3장) | 맞습니다. 지금 원점은 v1.0이 보내는 리더암 각도로 잡습니다. LeRobot 원격 조작은 (각자 캘리브레이션한) 리더암 값을 그대로 팔로워 목표로 보내므로, 수동 모드에서 잡은 리더암 각도는 그때 팔로워에 준 목표와 같습니다. 다만 팔로워의 실제 위치와는 다를 수 있어 팔로워 각도를 보내 주시면 그것을 쓰겠습니다 (1장 4). |
| 카메라 명령 응답이 요청서의 표와 다름 (2장) | 확인했습니다. 영상은 이제 안내대로 HTTP로 받아 카메라 명령을 보내지 않습니다 (8장). |
| 카메라 URL의 상대 경로 (4장) | HMI는 이미 그렇게 합니다. 영상 주소는 HMI가 붙은 웹소켓 주소의 호스트·포트를 쓰고 `ws`→`http`, `wss`→`https`로 바꿉니다. |

## 3. HMI에서 바꾼 것 (2026-10-16~17)

- HMI 화면: 대시보드 두 개를 없애고 조작 화면 하나만 React로 다시 만들었습니다 (2026-10-17). 버튼·안내·서버 통신(XML 명령·`Ping`·상태 묻기)은 그대로입니다. 서버 없이 시험할 때 쓰던 가짜 카메라 영상도 뺐습니다.
- 프로그램 종료: 확인 창 → 서버 연결을 닫고 종료 화면. 서버에는 아무것도 보내지 않으며 라인과 장비는 그대로입니다.
- 정지 키: `ProgramStop`을 보냅니다. (v1.0은 라인 상태를 보내지 않아 HMI가 가동 중인지 모르므로, 지금은 그 키가 늘 "시작"으로 보입니다. `Line`이 오면 가동 중에 "정지"로 바뀝니다.)
- 원점 복귀: 저장한 원점 각도를 `Home`에 실어 보내는 것이 기본입니다 (반영해 주신 대로).
- 거절 Reply에 `command`가 없으면 보낸 명령 이름으로 화면 문구를 고릅니다.
- 이벤트 `seq`: 다시 붙으면 지난 순번을 잊습니다.
- 밖에서 열기: Cloudflare(화면 파일 + `/ws/hmi` 웹소켓 중계 + 영상 세 경로, 앞에 Access)로 `https://hmi.hypefree.net/`에서 엽니다 (0.1). 화면은 자기를 내준 주소의 `/ws/hmi`에 붙습니다(설정 `wsUrl: 'auto'`). 메인 서버용 묶음(`wwwroot/` + 올리는 방법)을 만드는 도구도 남겨 둡니다.
- 카메라 영상: 보내 주신 안내대로 탑뷰·그리퍼 MJPEG와 `/video/status`를 붙였습니다 (8장).
- 로봇팔이 옮길 부품: 조작 화면에 "양품"·"불량품" 키를 더했습니다. 누르면 고른 값을 `SetSortTarget`으로 보냅니다 (0.5, 7장). 지금 서버는 받지 않아 화면에 그렇다고 안내합니다.
- 상태 간격: 서버의 상태 전송 간격(`PushIntervalMs`)을 바꿔도 되도록, 연결 확인과 상태 받기를 나눴습니다.
  - 연결 확인: HMI 화면마다 60초에 한 번 `Ping`을 보냅니다. 65초 넘게 아무 메시지(상태·`Pong`·답)가 없으면 끊김으로 봅니다. 서버가 연결을 닫으면 바로 압니다.
  - 상태: 서버가 보내는 간격대로 받습니다. 60초 넘게 오지 않을 때만 HMI가 `GetStatus`로 묻고, 원점 잡기 때 각도가 3초보다 오래됐으면 그때 한 번 묻습니다.
  - 이렇게 고치기 전에는 60초 간격에서 HMI가 약 4초마다 "연결 끊김"을 띄우고 다시 붙었습니다.
- HMI 쪽 확인용 시험 서버(서버 README와 회신을 보고 흉내 낸 것)도 회신 동작에 맞췄습니다. 실제 서버에도 붙여 확인했습니다 (6장).

## 4. 하드웨어 안전 정지

통신이 끊기면 DC 전원 케이블을 뽑으라는 HMI 안내에 대한 지적(전원을 끊으면 팔이 떨어지거나 남은 동작이 있을 수 있음)은 하드웨어 담당과 검토하겠습니다.
지금 HMI 문구는 키트 설명서의 비상정지 방법(DC 전원 케이블 분리)을 따른 것입니다. 검토 결과가 나오면 HMI 문구를 맞추겠습니다.

## 6. 실제 서버에 보내 본 결과 (2026-10-16~17)

받은 서버 주소(`ws://10.108.108.98:5080/ws/hmi`, 상태 `source="simulation"`)로 요청을 다섯 번 보냈습니다.
1·2회째는 요청 31개, 3회째는 값을 실을 수 있는 자리에 값을 넣은 16개, 4회째는 큰 값을 넣은 15개를 한꺼번에, 5회째는 긴급정지 16개(아래)를 보냈습니다. 모든 요청에 5~25ms 안에 답이 왔고 연결은 끝까지 유지됐습니다. 이벤트 등 다른 메시지는 오지 않았습니다.

| 보낸 것 | 답 |
|---|---|
| `SetMode`(`Auto`·`Manual`), `ProgramStart`, `ProgramStop`, `Home`(각도 없음, 각도 6개 — 서버가 보낸 지금 각도와 요청서 예시 각도), `EmergencyStop`, `EmergencyStopRelease` | `Received` / `ReceiptOnly`, `executed="false"` |
| `Stop`, 이름만 있는 `CameraStart`·`CameraStop` | `UnknownCommand` |
| `camera="top"`·`"close"`를 붙인 카메라 명령, 속성 추가, `Command` 두 개, `name` 없음 | `InvalidCommand` (`Command` 두 개·`name` 없음의 답에는 `command` 속성이 없음) |
| 원점 각도를 실은 `ProgramStart` (1장 3의 원점 사용을 정할 때를 위한 확인) | `InvalidCommand` — "Only Home accepts one Motors element." |
| `SetMode`의 `mode`가 틀리거나 없음 | `InvalidMode` |
| `Home` 각도 5개, 6번 `percent`, `NaN`, id 중복 | `InvalidAngles` |
| id 없는 `Command`, `version="2.0"`, 모르는 `type`, 본문이 있는 `GetStatus`, 깨진 XML, DTD | `Error` — 차례로 `MissingRequestId` · `UnsupportedVersion` · `UnknownType` · `InvalidRequest` · `InvalidXml` · `InvalidXml` |

- 지금 규약에서 명령에 값을 실을 수 있는 곳은 `SetMode`의 `mode`와 `Home`의 `Motors`(각도 6개)뿐입니다. 긴급정지·시작·정지·해제는 값이 없는 명령이고, 다른 값(카메라 이름, 시작에 실은 원점 각도)은 거절됩니다.
- HMI 세 화면(React로 옮기기 전)도 이 서버에 붙였습니다. 상태 표시(상태 미수신, 시험용 가상 데이터 안내, 장치 연결, 검사 개수, 리더암 각도), 버튼별 답 안내, 원점 잡기 → 원점 복귀(서버가 보낸 각도 6개를 실어 보냄), 프로그램 종료(서버로 보내는 메시지 없음)가 맞게 동작했습니다.
  React로 옮긴 조작 화면도 붙여 상태 표시(상태 미수신, 장비 없음 안내 — 그때 `source="unavailable"`, 장치 연결, 검사 개수 `–`)가 같게 나오는 것을 확인했습니다 (2026-10-17, 버튼은 누르지 않음).
- 큰 값 15개를 답을 기다리지 않고 한꺼번에 보냈습니다. `Home` 각도는 유한한 숫자면 모두 받았고(±180, 3600, 10만, 2147483647·4294967295, 1e20, 1.7976931348623157e308, 300자리 정수, 긴 소수), 1e309(무한대가 됨)만 `InvalidAngles`였습니다 — 각도 범위 검사는 아직 없습니다. `mode` 100글자는 `InvalidMode`, 요청 id는 64자까지 받고 65자는 `Error InvalidRequest`였습니다.
- 그 직후 서버 포트가 잠깐 닫혔다가 다시 열렸고, 그 뒤로는 상태 간격이 60초였습니다 (서버 담당이 바꿈). HMI를 위 3장대로 고친 뒤 60초 간격에서 확인했습니다. 70초 동안 HMI가 보낸 것은 60초째의 `Ping` 하나뿐이었고 끊김이 없었습니다. 각도가 25초 묵은 상태에서 원점 잡기를 누르자 `GetStatus`를 한 번 보내 지금 각도로 저장했습니다.
- 긴급정지 (2026-10-17): 한 번 보낸 뒤, id가 다른 10개를 한꺼번에(2ms 안에), 이어서 id까지 똑같은 5개를 한꺼번에 보냈습니다. 16개 모두 11~18ms 안에 `Received` / `ReceiptOnly`였고, 보낸 순서대로 답이 왔습니다.
  같은 id로 5번 보낸 것도 하나하나 따로 받아 같은 id의 답이 5개 왔습니다. 긴급정지는 여러 번 받아도 결과가 같지만, 장비를 연결한 뒤 시작 같은 명령이 같은 id로 다시 오면 두 번 실행될 수 있습니다.
  회신 6장 3차의 "실행 명령 중복 방지"에서 같은 id를 어떻게 다룰지도 정해 주세요 (제안은 0장 5번). HMI는 누를 때마다 새 id를 쓰고 자동으로 다시 보내지 않습니다.
- 카메라·로봇팔이 옮길 부품을 더한 뒤 (2026-10-17): 장비망 밖에서 `https://hmi.hypefree.net/`(Cloudflare)으로 붙었습니다. 서버 연결, "상태 미수신", 상태 `source="equipment"`와 장치 연결(로봇팔 연결 · 컨베이어 끊김)이 화면에 맞게 나왔습니다.
  양품 키를 눌러 `SetSortTarget target="Good"`을 한 번 보냈더니 거절되어, HMI가 "서버가 아직 … 명령(SetSortTarget)을 받지 않습니다"를 보였습니다. 영상 결과는 8.3입니다.

## 7. 로봇팔이 옮길 부품 — HMI가 고른 값을 보냅니다

### 7.1 HMI에서 바뀐 것

- 조작 화면의 운전 모드 아래에 **"로봇팔이 옮길 부품" — 양품 · 불량품** 키 두 개가 있습니다 (사용자 결정, 2026-10-17).
- HMI는 부품을 판정하지 않습니다. 작업자가 고른 값만 서버에 보냅니다.
- 정지 상태에서만 누를 수 있습니다 (운전 모드 전환과 같은 규칙). 누를 때마다 새 id로 `SetSortTarget`을 한 번 보내고, 자동으로 다시 보내지 않습니다.
- 서버가 받으면(`Received`) 그 값을 키에 눌린 모양으로 보입니다. 거절하면 이유를 키 아래에 보이고 값을 바꾸지 않습니다 (지금 서버: "서버가 아직 … 명령(SetSortTarget)을 받지 않습니다").
- 서버가 지금 값을 상태로 알려 주면(7.3) 키는 그 값을 따릅니다. 알려 주지 않는 동안은 그 브라우저에서 마지막으로 서버가 받아 준 값을 보이고 그렇다고 씁니다.

### 7.2 명령 `SetSortTarget`

```xml
<Message version="1.0" type="Command" id="hmi-k3f9-sortTarget-3">
  <Command name="SetSortTarget" target="Good" />
</Message>
```

| 항목 | 내용 |
|---|---|
| `target` | `Good`(양품) · `Defect`(불량품). 대소문자를 구분합니다 (`SetMode`의 `mode`와 같게) |
| 다른 속성·하위 요소·본문 | 넣지 않습니다 → `InvalidCommand` |
| `target`이 없거나 다른 값 | 제안: `Rejected` `code="InvalidTarget"` (`SetMode`의 `InvalidMode`와 같은 자리) |
| 받았을 때 | 지금은 다른 명령처럼 `Received` / `ReceiptOnly` / `executed="false"`면 됩니다 |
| Reply의 `target` | `SetMode`의 `mode`처럼 돌려주셔도 되고 빼셔도 됩니다 (HMI는 비교하지 않음) |
| 받을 수 없는 때 | 가동 중·긴급정지 중 등 서버가 받을 수 없을 때는 거절하셔도 됩니다. HMI는 거절 이유를 키 아래에 보입니다 (0.4 8번의 `NotStopped`·`EstopActive` 등) |

받음 답:

```xml
<Message version="1.0" type="Reply" timestamp="2026-10-17T01:00:00Z" id="hmi-k3f9-sortTarget-3">
  <Reply command="SetSortTarget" result="Received" code="ReceiptOnly" executed="false">
    <Detail>Command validated and received. No equipment action was executed or queued.</Detail>
  </Reply>
</Message>
```

서버 README의 파일 구성으로 보면 이렇게 고치면 됩니다 (구조가 다르면 맞게 바꿔 주세요).

- `Protocol.cs` 명령 검증: 허용 속성에 `target`을 이 명령에만 더하고(`SetMode`의 `mode`처럼), 명령 이름 목록에 `SetSortTarget`을 더하고, `target` 값을 검사하고, 정상이면 Reply.
- 통신 검사(`tests/Ecp.HmiServer.Checks`): 7.4의 항목.

### 7.3 (선택) 지금 값 알려 주기 — `Line/@sortTarget`

2차에서 `Line`을 보내실 때 서버가 가진 지금 값을 속성 하나로 더해 주시면, 여러 HMI가 같은 값을 보여 줍니다. 없어도 HMI는 동작합니다.

```xml
<Line state="Stopped" mode="Auto" emergencyStop="false" homeRequired="false" sortTarget="Defect" />
```

- 값은 `Good` · `Defect`. 모르면 속성을 빼 주세요 (확인하지 않은 값을 실제 값처럼 보내지 않는다는 회신의 원칙과 같음).
- 바뀔 때 이벤트 `SortTargetChanged`(`<Param name="target">Good</Param>`)를 보내 주시면 HMI 로그에 남깁니다 (선택).
- 서버를 켰을 때의 값, 이 값을 공정에서 어떻게 쓸지는 서버·장비 쪽에서 정하시면 됩니다.

### 7.4 확인 항목 (서버 통신 검사에 더할 것 제안)

| 보낸 것 | 기대하는 답 |
|---|---|
| `SetSortTarget target="Good"` · `target="Defect"` | `Received` |
| `target="Maybe"` · `target="good"` · `target` 없음 | `Rejected` (제안 `InvalidTarget`) |
| `target`과 다른 속성을 함께(예: `mode="Auto"`) · 하위 요소 · 본문 | `Rejected` `InvalidCommand` |
| (7.3을 하시면) HMI 두 개에서 A가 바꿈 | B가 주기 전송을 기다리지 않고 바뀐 상태를 받음 |

HMI 쪽 시험 서버(파이썬)가 이 표대로 답합니다. 동작 견본이 필요하시면 보내 드리겠습니다.

## 8. 카메라 영상 — 보내 주신 안내 반영 결과

### 8.1 HMI가 한 것

- 카메라 화면 하나에 탑뷰(`/video/1.mjpg`, id 1)와 그리퍼(`/video/2.mjpg`, id 2)를 바꿔 봅니다 (안내 3장의 방법 B, `img`). 한 화면이 동시에 여는 영상 연결은 하나입니다.
- "카메라 연결"을 누른 동안만 `/video/status`를 묻습니다: 앞 조회가 끝난 뒤 1초, 제한 3초, 캐시 안 함, 브라우저 탭이 숨으면 쉼. 카메라는 배열 순서가 아니라 `id`로 찾습니다.
- 안내 5장의 표대로 "설비 영상 연결 대기" · "영상 미수신" · "5초 이상 새 영상 없음" · "영상 상태 확인 불가"를 보이고 그동안 영상을 숨깁니다. 200 응답만으로 정상이라 하지 않고 첫 장면이 그려진 뒤 보이며, 끊기면 1초 → 2초 → 4초, 최대 5초 간격으로 `?t=`를 붙여 다시 엽니다.
- `CameraStart`·`CameraStop`은 보내지 않고 `/ws/video`에는 붙지 않습니다. 영상이 끊겨도 `/ws/hmi`는 그대로이고, `/ws/hmi`가 끊겨도 영상은 계속 봅니다.
- 카메라 연결 표시는 `/video/status`로만 정합니다 (XML의 `RobotArm/@connected`나 `source`로 대신하지 않음).

### 8.2 주소와 브라우저 출처 (안내 8장)

서버에 CORS가 없으므로, HMI는 화면과 영상이 늘 같은 주소에서 오게 엽니다. 서버 쪽 할 일은 없습니다.

| HMI를 여는 곳 | 영상이 가는 길 |
|---|---|
| 장비망 밖 `https://hmi.hypefree.net/` | Cloudflare Worker가 `/ws/hmi`와 영상 세 경로(`/video/status` · `/video/1.mjpg` · `/video/2.mjpg`, GET·HEAD만)만 Access 서비스 토큰을 붙여 Tunnel로 → `http://192.168.219.101:8000`. 그 밖의 경로(`/`, 확인 화면 `/video` 등)는 밖에 열지 않음 |
| 장비망 안 다른 PC | HMI 담당 PC의 개발용 서버(`http://<HMI 담당 PC>:8080/?mock=0&ws=auto`)가 `/ws/hmi`와 `/video/…`를 서버로 그대로 이음 |
| 서버가 HMI 화면을 내줄 때 (지금은 안 함) | 원래 같은 주소 |

- 영상 경로나 포트를 바꾸시거나 HTTP 경로를 더 만드시면 알려 주세요. Cloudflare 쪽 목록을 고쳐야 합니다.
- 서버가 `Host` 머리말을 검사하신다면 Tunnel로 온 요청의 `Host`가 서버 주소와 다를 수 있습니다. 문제가 되면 알려 주세요. Tunnel에서 `192.168.219.101:8000`으로 바꿔 보낼 수 있습니다.

## 9. HMI로 확인하는 방법

- 장비망 밖: `https://hmi.hypefree.net/` → 이메일 입력 → 받은 일회용 코드 (허락한 이메일만, 0.1). 서버 점검 페이지는 `/tools/server-check.html`(형식 XML)입니다.
- 장비망 안: HMI 담당 PC가 개발용 서버를 켜 두면 `http://<HMI 담당 PC>:8080/?mock=0&ws=auto` (그때 주소를 알려 드리겠습니다).
- 지금 서버에서 보이는 것: 상태 "상태 미수신", 양품·불량품 키를 누르면 "서버가 아직 … 명령(SetSortTarget)을 받지 않습니다", 카메라 연결을 누르면 영상(설비 업로드가 꺼져 있으면 "설비 영상 연결 대기").
- `SetSortTarget`(7.2)을 반영하시면 키 아래 안내가 "서버가 명령을 받았습니다. 아직 장비는 움직이지 않습니다(서버 규약 v1.0)."로 바뀌고 고른 키가 눌린 모양이 됩니다. `Line/@sortTarget`(7.3)이 오면 키가 서버의 값을 따라갑니다.
